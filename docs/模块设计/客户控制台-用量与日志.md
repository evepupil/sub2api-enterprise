## 1. 职责与边界

用量页回答「花了多少、花在哪」，日志页回答「某一次调用发生了什么」。2026-10-03 起用量页接通后端，2026-10-04 起日志页接通后端，都只看登录账号自己的数据；日志页只列计费成功的调用。组织的普通成员在用量页最上面多一张「组织配额」卡片（2026-10-04：组织页只给组织管理员，成员的组织配额与申请放在这里）。

## 2. 结构与数据流

- 用量的取数：浏览器 → 官网接口 `/api/portal/console/usage?from&to&detail=1`（带着登录状态，凭证过期自动续期）→ 后端 `/api/v1/usage/dashboard/overview`（技术设计 18.2）。打开页面取两份：所选范围的明细（合计、每天或每小时的合计、按模型 / 密钥 / 分组的拆分）和最近 53 周的每天合计（热力图）。换范围只重取明细；切指标不重取；刷新按钮两份都重取。
- 「今天」按北京时间、取浏览器的真实时间（页面挂载后才读，静态页面里没有日期）；预设范围跟着今天走，「全部」从账号创建那天算起（最长 1100 天）。一天的范围按小时取、按 24 小时出柱，多天按天。
- 用量的换算（`src/lib/console/live/usage-view.ts`）：四张数字卡（Token 与缓存命中、请求与成功率、平均耗时与首字、消费：本期计费与每月约多少）；热力图 + 范围内的活跃天数 / 最长连续 / 本期消费 / 最活跃日（两份数据按天合并，范围数据为准）；明细指标（Token / 请求数 / 费用）× 三个维度 → 三张堆叠柱状图，超过 5 个系列的排名后几位合成「其他」。
- 日志的取数：浏览器 → 官网接口 `/api/portal/console/logs`（一页记录）、`/logs/options`（筛选选项：账号的密钥、这段时间用过的模型）、`/logs/export`（CSV）→ 后端现有的使用记录接口 `/api/v1/usage`（只有计费成功的调用，后端分页，从新到旧）、`/api/v1/keys`、`/api/v1/usage/dashboard/models`。官网服务器只挑页面要用的字段，后端记录里带的完整密钥不往外传。
- 日志：筛选（时间、密钥、模型、类型、流式）→ 后端分页表格；每行：时间、密钥（下一行分组与倍率）、模型（开了 Fast 的带标签）、Token（下一行缓存读写）、费用（后面的「i」悬停看费用明细）、耗时（总耗时与首字两个徽标，下一行流式与输出速度），可选列推理强度（模型后面）、IP（最后）；「列设置」决定显示哪些列；行菜单复制请求 ID、复制为 curl、看详情；详情抽屉列全部字段；导出 CSV 按当前筛选最多 1 万条。

## 3. 关键决策

- 后端新加一个用量总览接口，一次给齐「每天 × 模型 / 密钥 / 分组」，不拿现有接口拼（2026-10-03 用户选的方案二）：拼的话打开一次页面要问后端十几次，会撞上每个用户每分钟 60 次统计查询的限流。
- 数字卡口径：「请求」是计费成功的请求；成功率 = 成功 ÷（成功 + 失败），失败数来自后端错误日志，拿不到时这一行不显示；「输入」含写入缓存的部分，「缓存」是命中缓存的部分，三项加起来等于总 Token；首字耗时只算记录了首字的请求（流式文本），没有时这一行不显示。金额是实际扣费（已乘分组倍率）。
- 模型名直接显示调用时的模型名，不换成官网目录里的展示名：和日志、账单对得上。密钥、分组显示后端的名字，没有分组的请求叫「未分组」。
- 组织管理员也只看自己的用量（用户确认）；全组织的成员用量放在组织页。
- 换范围时先留着旧数据（变浅），新数据到了再换；首次加载显示与真实内容等高的占位块；取不到数据时整页显示出错与「重试」，太频繁时提示稍后再试。
- 热力图固定显示最近一年，右侧四格跟着范围变：一年视图看习惯，范围统计看本期。
- 明细图超过 5 个系列合并成「其他」，颜色顺序固定，「其他」用灰色。
- 日志只列计费成功的调用，不显示失败请求，也不按请求 ID 搜索（2026-10-04 用户确认：客户不知道请求 ID）；信息参照用户给的参考截图（去掉渠道、用户两列），版式按控制台风格（用户要求不照搬）。
- 不单列「计费」（2026-10-04 用户要求去掉）。费用后面一个「i」，悬停（或点一下固定）弹出费用明细，内容和 sub2api 使用记录里费用旁的悬浮明细一致（用户要求，样式用控制台卡片）：有的分项费用（输入、输出，图片输入、输出）；按 Token 计费的列每百万 Token 单价（这次的分项费用 ÷ 对应 Token 数反算，图片 Token 单独算），按张生图列张数、计费尺寸、尺寸来源、输入输出尺寸、各尺寸张数、单张价格与图片总价，按次计费列单次价格；缓存创建、读取费用；下面是服务档位、倍率、官方价（没乘倍率）与实际扣费（sub2api 叫原始与用户扣费，2026-10-04 用户要求统一成和日志详情、导出表格一样的叫法）。哪一项什么时候出现照 sub2api 的规则；金额 6 位小数、单价 4 位小数，币种照控制台写 US$，倍率用分组倍率徽标。
- 开了 Fast 的调用（Codex、Claude 的 Fast 模式，后端记成 priority 或 fast，默认按两倍计费；Codex 的 Ultrafast 标「Ultrafast」）在模型名旁标一个橙色标签，普通调用和低价的 flex 不标（2026-10-04 用户确认保留）；导出表里对应「Fast 模式」一列。
- 详情里不写「官方价 × 倍率 = 实际扣费」的等式：遇到高峰、分时段加价时等式对不上。
- 「列设置」（2026-10-04 用户要求，参照用户给的勾选列表截图）：时间固定显示；默认显示原来那几列（密钥、模型、Token、费用、耗时），新加的推理强度、IP 默认不显示，要勾上才有；勾好点「保存」才生效，「重置」回到默认勾选。设置存在这台浏览器里（和模型收藏一样，换设备不同步），存的是每一列显示与否：以后加了新列，存过设置的人也按新列的默认值走。导出 CSV 不跟着列设置变，总是全部字段（含 IP）。
- 导出由官网服务器分页向后端要（每次 1000 条，最多 1 万条）再拼成 CSV：浏览器只发一次请求；单元格以 = + - @ 开头时前面加单引号，防止表格软件当公式执行。
- 消费卡只讲钱：大数字是本期计费，右上角是按天数折算的「每月约多少」，下面一行固定写「本期计费」。生图张数和花钱无关，不放在这张卡上（用户要求）。

## 4. 当前实现

- 用量页（真实数据）：标题行是余额卡片、时间范围与刷新（余额卡片 2026-10-09 用户要求，照 sub2api 顶栏的余额：浅蓝底、钱包图标加可用余额，和旁边按钮同高 40，点了去账单页；读的是账单页同一份余额，跟着「刷新」一起重读，读不到时不显示；手机上放不下时刷新换到下一行）；四张数字卡（Token 与缓存命中、请求与成功率、平均耗时与首字耗时、消费：如「约 US$15.09/月」「US$15.09」「本期计费」，成功率与首字拿不到时那一行不显示）；活动面板里热力图打开时停在最近几周，下面四个小格（超宽屏才与热力图左右并排）；用量明细切换 Token / 请求数 / 费用，三张堆叠柱状图（按模型、按 API 密钥、按分组），悬停或方向键看当天明细，「今天」「昨天」和自选的一天按小时出柱；加载中显示占位块，出错显示「重试」。
- 日志页（真实数据）：筛选栏（时间、密钥、模型、类型、流式，清除筛选、导出 CSV）；标题行下方右侧是清除筛选、列设置、导出 CSV；表格最窄宽度按显示的列加起来（默认 930），小屏横向滚动，时间列与操作列固定（手机上时间列不固定），各列内容见上；分页由后端做（每页 10 / 20 / 50 条）；首次加载显示占位块，换条件时旧数据变浅，出错显示「重试」，导出失败在按钮旁提示；详情抽屉关闭后焦点回到打开它的按钮。
- 组织配额卡片（只给组织的普通成员）：剩余额度与下次重置时间、申请额度、最近 3 条申请与撤回，详见[客户控制台-密钥与组织](./客户控制台-密钥与组织.md)；标题行的刷新一起重取。
- 刷新按钮、加载占位块、分组倍率徽标、悬浮说明卡片（费用明细用）、列设置用共享组件；用量页 7 个文件（含组织配额卡片 2 个）、日志页 10 个文件；真实数据层 `src/lib/console/live/` 用量 5 个、日志 3 个文件，列设置的存取 1 个。

## 5. 验证方式

- 单测：占位数据部分见框架模块（用量汇总、明细拆分、热力图、日志筛选与导出）；真实数据部分 `tests/console-usage-live.test.ts`（数字卡口径、成功率与首字的显示条件、每天合计与合并、按天 / 按小时的明细与「其他」、「全部」的起点、热力图起点、真实时间快照、官网接口参数校验与后端结果转换）、`tests/console-usage-route.test.ts`（转发带凭证、参数错误、没登录、太频繁、后端数据看不懂）；后端 `usage_handler_overview_test.go`、`usage_log_repo_overview_test.go`。
- 后端实测（2026-10-03，本机测试后端、测试账号 9 月 14–27 日 84 次调用）：新接口的合计与现有统计接口一致（84 次、1,851,612 Token、US$15.0864、平均 4810.5 ms），按天合计、按模型合计都加得回总数；一天按小时、一年不拆分、参数错误都按预期。
- 浏览器实测（Edge 无头，开发服务）：登录后用量页显示 1.85M Token、84 次、成功 100%、4.81 s、US$15.09，热力图 14 个活跃日，三张图分别是 3 个模型、1 把密钥、2 个分组；「今天」全是 0、三张图提示没有调用；自选 9 月 27 日按 24 小时出柱；切「费用」图跟着变；手机宽度不横向溢出。
- 日志页（2026-10-04）：单测 `tests/console-logs-live.test.ts`（筛选与分页参数校验、后端地址、记录转换不带出完整密钥与生图字段、筛选选项、费用明细在按 Token、按 Token 的生图、按张生图、老生图记录、按次几种调用下列哪些项与单价反算、服务档位、Fast 标签、输出速度、curl 示例、CSV 转义与防公式和 Fast 列、筛选是否偏离默认）、`tests/console-column-prefs.test.ts`（列设置的存取：没存过或格式不对用默认、锁定的列总在、后来加的列按默认、日志表默认列与最窄宽度）、`tests/console-logs-route.test.ts`（没登录 401、参数不对 400、列表只回需要的字段、筛选选项一项读不到时为空、导出分页要全并带 UTF-8 标记）。本机测试库给测试账号的 84 条记录补了分项费用、首字耗时、服务档位与推理强度（总价不变，`.fleet/local-backend/console-logs-fixtures.sql`）。浏览器实测（Edge 无头，开发服务）：最近 30 天 84 条、第一页 20 行；按模型 gpt-5.4 筛出 28 条；第 2 页正常；详情抽屉字段齐全；导出 CSV 84 行、中文表头；手机宽度不横向溢出。去掉计费列后（`.fleet/login-wiring/logs-cost-browser.mjs`）：表头为时间、密钥、模型、Token、费用、耗时、操作；鼠标移到费用旁的「i」弹出费用明细（分项费用、单价、缓存读取费用、服务档位、倍率、官方价、实际扣费），移开收起，点一下后移开仍在，Esc 收起；Fast 调用的档位显示 Fast；手机宽度下卡片在屏幕内。列设置（`.fleet/login-wiring/logs-columns-browser.mjs`）：默认勾选时间（置灰）、密钥、模型、Token、费用、耗时；勾上推理强度、IP 保存后表头多这两列、刷新后还在；不保存按 Esc 关掉不变；重置加保存回到默认；时间取消不了；手机宽度不横向溢出、面板在屏幕内。本机测试库给 84 条记录补了调用方 IP（文档专用地址段，`.fleet/local-backend/console-logs-ip-fixtures.sql`）。
