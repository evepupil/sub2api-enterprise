## 1. 职责与边界

用量页回答「花了多少、花在哪」，日志页回答「某一次请求发生了什么」。2026-10-03 起用量页接通后端，显示登录账号自己的真实用量；日志页仍是请求样本，不接后端。

## 2. 结构与数据流

- 用量的取数：浏览器 → 官网接口 `/api/portal/console/usage?from&to&detail=1`（带着登录状态，凭证过期自动续期）→ 后端 `/api/v1/usage/dashboard/overview`（技术设计 18.2）。打开页面取两份：所选范围的明细（合计、每天或每小时的合计、按模型 / 密钥 / 通道的拆分）和最近 53 周的每天合计（热力图）。换范围只重取明细；切指标不重取；刷新按钮两份都重取。
- 「今天」按北京时间、取浏览器的真实时间（页面挂载后才读，静态页面里没有日期）；预设范围跟着今天走，「全部」从账号创建那天算起（最长 1100 天）。一天的范围按小时取、按 24 小时出柱，多天按天。
- 用量的换算（`src/lib/console/live/usage-view.ts`）：四张数字卡（Token 与缓存命中、请求与成功率、平均耗时与首字、消费：本期计费与每月约多少）；热力图 + 范围内的活跃天数 / 最长连续 / 本期消费 / 最活跃日（两份数据按天合并，范围数据为准）；明细指标（Token / 请求数 / 费用）× 三个维度 → 三张堆叠柱状图，超过 5 个系列的排名后几位合成「其他」。
- 日志：筛选条件（时间、密钥、模型、状态、类型、流式、请求 ID）→ `filterLogs` → 分页表格；行菜单复制请求 ID、复制为 curl、看详情；详情抽屉列出全部字段与请求示例；导出当前筛选结果为 CSV。

## 3. 关键决策

- 后端新加一个用量总览接口，一次给齐「每天 × 模型 / 密钥 / 通道」，不拿现有接口拼（2026-10-03 用户选的方案二）：拼的话打开一次页面要问后端十几次，会撞上每个用户每分钟 60 次统计查询的限流。
- 数字卡口径：「请求」是计费成功的请求；成功率 = 成功 ÷（成功 + 失败），失败数来自后端错误日志，拿不到时这一行不显示；「输入」含写入缓存的部分，「缓存」是命中缓存的部分，三项加起来等于总 Token；首字耗时只算记录了首字的请求（流式文本），没有时这一行不显示。金额是实际扣费（已乘通道倍率）。
- 模型名直接显示调用时的模型名，不换成官网目录里的展示名：和日志、账单对得上。密钥、通道显示后端的名字，没有通道的请求叫「未分组」。
- 组织管理员也只看自己的用量（用户确认）；全组织的成员用量放在组织页。
- 换范围时先留着旧数据（变浅），新数据到了再换；首次加载显示与真实内容等高的占位块；取不到数据时整页显示出错与「重试」，太频繁时提示稍后再试。
- 热力图固定显示最近一年，右侧四格跟着范围变：一年视图看习惯，范围统计看本期。
- 明细图超过 5 个系列合并成「其他」，颜色顺序固定，「其他」用灰色。
- 日志只是样本，条数与用量页的合计不一一对应（接后端后由接口分页返回）。
- 消费卡只讲钱：大数字是本期计费，右上角是按天数折算的「每月约多少」，下面一行固定写「本期计费」。生图张数和花钱无关，不放在这张卡上（用户要求）。

## 4. 当前实现

- 用量页（真实数据）：标题行是时间范围与刷新；四张数字卡（Token 与缓存命中、请求与成功率、平均耗时与首字耗时、消费：如「约 US$15.09/月」「US$15.09」「本期计费」，成功率与首字拿不到时那一行不显示）；活动面板里热力图打开时停在最近几周，下面四个小格（超宽屏才与热力图左右并排）；用量明细切换 Token / 请求数 / 费用，三张堆叠柱状图（按模型、按 API 密钥、按通道），悬停或方向键看当天明细，「今天」「昨天」和自选的一天按小时出柱；加载中显示占位块，出错显示「重试」。
- 日志页：筛选栏（时间、密钥、模型、状态、类型、流式、请求 ID 搜索、清除筛选、导出 CSV）；表格 1040 宽在小屏横向滚动，操作列固定，行菜单可复制请求 ID、复制为 curl、看详情；详情抽屉列全部字段与请求示例，关闭后焦点回到打开它的按钮；导出的 CSV 带 UTF-8 标记，Excel 打开中文不乱码；没有结果时显示空状态与清除筛选。
- 刷新按钮、加载占位块用共享组件；用量页 5 个文件、日志页 8 个文件；用量的真实数据层 `src/lib/console/live/` 5 个文件。

## 5. 验证方式

- 单测：占位数据部分见框架模块（用量汇总、明细拆分、热力图、日志筛选与导出）；真实数据部分 `tests/console-usage-live.test.ts`（数字卡口径、成功率与首字的显示条件、每天合计与合并、按天 / 按小时的明细与「其他」、「全部」的起点、热力图起点、真实时间快照、官网接口参数校验与后端结果转换）、`tests/console-usage-route.test.ts`（转发带凭证、参数错误、没登录、太频繁、后端数据看不懂）；后端 `usage_handler_overview_test.go`、`usage_log_repo_overview_test.go`。
- 后端实测（2026-10-03，本机测试后端、测试账号 9 月 14–27 日 84 次调用）：新接口的合计与现有统计接口一致（84 次、1,851,612 Token、US$15.0864、平均 4810.5 ms），按天合计、按模型合计都加得回总数；一天按小时、一年不拆分、参数错误都按预期。
- 浏览器实测（Edge 无头，开发服务）：登录后用量页显示 1.85M Token、84 次、成功 100%、4.81 s、US$15.09，热力图 14 个活跃日，三张图分别是 3 个模型、1 把密钥、2 个通道；「今天」全是 0、三张图提示没有调用；自选 9 月 27 日按 24 小时出柱；切「费用」图跟着变；手机宽度不横向溢出。
- 交互检查表见页面规格末尾。

## 6. 待扩展项

- 日志改读请求记录接口（服务端分页与筛选）；导出改为服务端生成。
- 用量页按密钥、按模型筛选（后端总览接口已支持 `api_key_id`、`model` 参数）。
- 日志详情链接到工单（「就这条请求提工单」）。
