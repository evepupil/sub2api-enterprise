## 1. 职责与边界

版式照模板登录、注册页（左表单右展示、无顶栏页脚）。本轮只做前端：提交只做校验与加载态，不调用接口；谷歌登录按钮占位。

## 2. 结构与数据流

- 登录：只填邮箱、密码，界面不区分个人与组织账号（后端按邮箱登录，账号归属由后端判断）。
- 注册：「个人注册 / 创建组织」切换存网址 `?account=personal|organization`；创建组织多一个组织名称，邮箱为管理员邮箱。登录与注册互相跳转不带参数。
- 邀请码：由站点配置「邀请码注册」开关决定，开启时显示且必填，关闭时不显示。接后端前开关写死为开启；接入后改读后端公开设置 `invitation_code_enabled`。
- 校验：必填、邮箱格式、密码至少 8 位、（显示时）邀请码必填；所有出错字段同时标红，焦点落在第一个出错项。
- 文档页只有标题和去模型页、价格页的按钮；404 页大号「404」加返回首页。

## 3. 关键决策

- 登录不区分账号类型：个人与组织成员都用邮箱登录，没有必要让用户先选身份。
- 邀请码只在开启邀请码注册时出现：关闭时注册页更简洁。与需求设计 3.2「邀请码框始终保留、关闭时作为选填的组织邀请码入口」不同，关闭邀请码注册时加入已有组织的入口待用户确认（见需求设计 12.1 的说明）。
- 不写「暂未开放」之类提示：提交通过校验后只显示加载态再恢复。

## 4. 当前实现

- 登录：顶部品牌、语言与主题切换；邮箱、带显示切换的密码、忘记密码；校验时所有出错字段同时标红并聚焦第一个；通过后按钮加载 1.2 秒；去注册链接；谷歌按钮占位；条款链接。
- 注册：个人注册与创建组织切换（平分宽度）；邮箱、密码、邀请码（开关开启时，必填）；创建组织多组织名称；校验与加载同登录；去登录链接。
- 右侧展示：浅灰底虚线框，6 个厂商标志叠放与一句说明，仅大屏显示。
- 文档页：标题加去模型、价格的按钮；404：大号 404、页面不存在、返回首页。

## 5. 验证方式

交互检查表见页面规格末尾（登录只有邮箱密码、两种校验错误、密码显示切换、注册邀请码必填、注册通过、创建组织模式、文档页、404）。

## 6. 待扩展项

- 接入现有注册与登录接口（个人注册、创建组织、邀请码预校验、找回密码、双重验证）；邀请码开关改读后端公开设置。
- 关闭邀请码注册时加入已有组织的入口（例如邀请链接自动带上组织邀请码），待用户确认。
- 谷歌登录接入第三方登录配置。
