# ACF 组织防护插件页模块设计

模块定位：给组织管理员（以及跨组织运营的平台管理员）一个控制台页面，展示本组织经过 ACF 安全网关的防护数据；数据来自 ACF 侧 M8 只读接口，由 Sub2API 后端代理并以「用户断言」认证。

## 1. 职责与边界

本模块负责：

- 签发用户断言：代理每次数据调用前当场重验组织身份，签出短时 EdDSA 断言（claims 仅 iss/aud/sub/org/iat/exp）。
- 代理五组只读查询到 ACF：总览（三口径+空窗+处置分布）、趋势、风险类型分布、成员触发榜、最近风险事件。
- 控制台插件页：KPI 卡、处置/类型分布图、趋势图、成员榜、最近事件表。
- 断言密钥对管理：Ed25519 密钥的生成、持久化、公钥导出。

本模块不负责：

- 任何对 ACF 的写操作（策略、能力配置、原文查看都在远期 SSO 项）。
- 逐条审计明细调查（付费层，ACF 侧 M8.5）。
- JWKS 公钥自动发布（静态公钥；SSO 立项时升级）。

## 2. 认证模型（与 ACF 的契约）

拓扑锁死「代理 + 逐请求签发」：浏览器只和 Sub2API 后端对话（无跨域、无暴露 ACF），后端在每次数据调用前当场重验组织身份并签发断言——成员被移出组织即时生效，无残余窗口。ACF 验签（EdDSA 白名单、iss/aud 校验、exp 必填、±1 分钟容忍）后按断言里的组织过滤返回，组织来自令牌、无参数可篡改。

- **断言密钥**：独立 Ed25519 密钥对，不复用控制台 jwt.secret（HMAC 共享会打穿信任边界），不与身份解析的共享凭证重叠。私钥 PKCS8 PEM 存 DATA_DIR（0600，坏了拒绝启动而非静默换钥），可用 `acf.plugin.private_key` 外部注入；公钥以 PKIX PEM 交给部署者贴进 ACF 端点配置。
- **claims 最小化**：iss/aud/sub/org/iat/exp（+ JWT 头 kid=公钥哈希前缀）。砍掉 username 与 role：界面人名用身份解析落库的归属数据，只读接口无角色 gating 用途。
- **编号铁律**：断言的 sub/org 与身份解析返回的编号完全同源（主键的十进制字符串），「谁在查数据」和「谁触发了安全事件」对得上同一个人。有专门测试钉死。
- **错误语义**：401 invalid_assertion（断言无效/过期）、400 bad_request、404 org_not_found（组织未接入，不泄露存在性）；我方代理补充 502 acf_unavailable（ACF 不可达）与 403 forbidden（非组织管理员）。

## 3. 授权模型

| 调用者 | 组织范围 | 说明 |
| --- | --- | --- |
| 平台管理员（role=admin） | 必须显式传 `org_id`，可查看任意存在的组织 | 组织来自参数但经服务端校验存在性，且断言里签的是这个 ID |
| 组织管理员（组织的 is_owner） | 本人组织，禁止传其他组织 ID | 范围来自会话归属 |
| 其他用户（个人用户/普通成员） | 一律 403 | 对齐 ACF 需求 7.1「组织管理员可以查看」 |

## 4. 结构与数据流

```
插件页(Vue) ──GET /api/v1/acf-plugin/{endpoint}──> 会话认证 + 面板限流
                                        │
                        AuthorizePluginView（当场重验组织身份）
                                        │
                        SignAssertion（Ed25519，5 分钟）
                                        │
              GET {acf.plugin.base_url}/api/v1/plugin/{endpoint}?from&to
              Authorization: Bearer <断言>        │
                                        │
                     ACF 状态码与 JSON 原样透传（代理层不二次解释）
```

五条代理端点：`summary / trend / risk-types / top-actors / recent-events`；查询参数只接受 `from`/`to`（RFC3339，缺省近 30 天，上限 90 天，与 ACF 侧一致）。`acf.plugin.base_url` 为空 = 功能关闭，处理器对所有请求返回 404 feature_disabled。

## 5. 关键决策

| 决策 | 结论 | 理由 |
| --- | --- | --- |
| 拓扑 | 后端代理，浏览器不直连 ACF | 无 CORS、不暴露 ACF、签发点天然在权限校验之后 |
| 签发时机 | 逐请求，签发前当场重验成员身份 | 撤销/停用即时生效，无残余窗口 |
| 公钥分发 | 静态公钥钉 ACF 端点配置；JWKS 随 SSO 立项升级 | 单 ACF 对单 Sub2API 的部署面用不上自动轮换 |
| 页面可见性 | 组织管理员看本组织；平台管理员选组织看全站 | 需求方 2026-09-18 拍板 |
| 签名算法 | Ed25519（EdDSA） | 密钥短、签名快；ACF 为 Go 侧无兼容问题；算法白名单防 alg 混淆 |
| 响应处理 | ACF 状态码与 JSON 原样透传 | 语义由契约共同保证，代理层保持薄 |

## 6. 验证方式

- 服务单测：断言可被「ACF 验证规则的可执行镜像」（EdDSA 白名单 + iss/aud + exp 必填 + kid）验证且编号与身份解析同源；密钥文件生成/重载一致/损坏拒绝启动/Unix 权限收紧；授权矩阵（组织管理员、普通成员、无组织用户、平台管理员三态、跨组织 403）；代理透传上游状态与响应体；未知端点拒绝；功能关闭语义。
- 处理器单测：未认证 401、功能未配置 404、组织管理员放行、非管理员 403、平台管理员三态（缺参 400/成功/组织不存在 404）、时间窗口非法 400、上游不可达 502 且被拒请求绝不打到 ACF。
- 门禁：后端 `go build` / `go test` / `golangci-lint`，前端 `vue-tsc` / `eslint`（2026-09-18 全绿）。
- 真实联调：等 ACF m8-1 端点部署后，以本机真实密钥走全链路（归属与断言同人、五端点有数据）。
