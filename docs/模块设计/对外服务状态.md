## 1. 职责与边界

本模块负责：

- 一个匿名可访问的接口，返回脱敏后的服务状态。
- 一个对外状态页，展示整体可用率、各监测项状态与探测时间线。
- 平台开关，决定是否对外开放。

本模块不负责：

- 采集与统计。状态、延迟、可用率、时间线全部由已有的渠道监测服务算好。
- 控制台内部的监控页面。那套给运维看细节，两者受众不同。
- 故障公告与事件时间线，见待扩展项。

## 2. 数据源为什么选主动探测

平台内有两套监控：

| | v2 渠道监控 | v1 渠道监测 |
|---|---|---|
| 原理 | 真实流量被动聚合 | 管理员配置的主动探测 |
| 零流量时 | 无数据 | 照常有信号 |
| 公示范围由谁定 | 自动全量 | 管理员建监测项 |

选 v1 有两个理由。探测项由管理员显式创建，这本身就是「哪些东西要对外公示」的开关，不需要另造一套白名单；而且状态页在低峰期也必须有信号，被动聚合在零流量时只能显示无数据。

最初误用了 v2，表现为页面上所有项恒为「无数据」，改用 v1 后代码反而更薄——可用率与时间线都不用自己算。

## 3. 脱敏规则

`ListUserView` 已经为登录用户脱过一道敏，对匿名访客还要再收一道。

| 外发 | 不外发 | 原因 |
|---|---|---|
| 监测项名称 | 上游厂商标识 | 等于把供应链写在官网 |
| 所属分组 | 模型名 | 同上，且属商务信息 |
| 状态档位 | 配额快照 | 我们自己账号的余量 |
| 近 7 天可用率 | 监测项 ID | 内部标识 |
| 链路延迟、响应延迟 | 错误详情 | 可能含上游返回内容 |
| 接口形态 | | 协议名，不含厂商信息 |

**监测项名称与分组名原样外发**，后台命名即对外文案。建监测项时不要把上游厂商名写进名称。

## 4. 状态档位

内部四档折成对外三档加未知：

| 内部 | 对外 |
|---|---|
| `operational` | 正常 |
| `degraded` | 性能下降 |
| `failed` / `error` | 不可用 |
| 其他 | 无数据 |

`failed` 与 `error` 对访客是同一件事，合并。整体状态取所有监测项中最差的一档；「无数据」排在「正常」之前参与比较，避免一个尚未探测的项把整体拉成故障。

整体可用率是各监测项可用率的**算术平均**，不按流量加权——加权需要流量数据，而流量数据本身不对外。

## 5. 安全设计

- **默认关闭**，由平台管理员显式打开。
- **fail-closed**：设置读取失败按关闭处理。接口匿名可达，不确定状态必须按最严处理。
- **关闭返回 404 而非 403**：不向未认证调用方确认接口存在。
- **整体缓存一分钟**：匿名接口会被刷。
- **公网限流**：复用已有的 `PublicIP` 限流器。
- 导航入口由 `public_status_enabled` 控制，关闭时首页与页脚都不出现「服务状态」，避免点进去看到空页。

## 6. 页面结构

顶部两张汇总卡：近 7 天可用率、监测项正常数。下面每个监测项一张卡，含状态圆点、名称、状态徽章、接口形态与分组标签，右侧三项指标（可用率、链路延迟、响应延迟），下方一条探测状态条。

汇总数字使用等宽数字保证跳动时对齐，字距与官网统一为零。

状态条用固定宽度的竖长条并允许换行。等分铺满会把格子压成一两像素，颜色失去辨识度。

链路延迟与响应延迟分开展示：前者衡量网络往返，后者含上游生成时间。合并成一个数会让客户误判——上游生成本身就要数秒。

## 7. 当前实现

- 接口：`GET /api/v1/status`，匿名可访问。
- 开关：`public_status_enabled`，默认 false，随公开设置下发给前端控制导航显隐。
- 页面：`/status`，不需要登录。
- 窗口：7 天，与监测服务的可用率窗口一致。

为支持接口形态标签，`UserMonitorView` 增加了 `APIMode` 字段（值域 `chat_completions` / `responses`）。该字段为协议标识，不含厂商信息。

## 8. 验证方式

- 后端 `go build` 与 `go vet` 全过；公开设置字段一致性单测通过。
- 前端类型检查、静态检查与 269 个文件 1984 条单测全过。
- 开关为 false 时接口返回 404、公开设置中该字段为 false，已实测确认。
- 打开开关后接口正常返回，返回体确认不含厂商标识、模型名与配额信息。

## 9. 决策记录

| 决策 | 结论 | 说明 |
|---|---|---|
| 数据源 | 主动探测 | 公示范围由管理员决定；零流量仍有信号 |
| 是否自行统计 | 否 | 可用率与时间线监测服务已算好，重算会出现两套口径 |
| 关闭时的响应码 | 404 | 403 会确认接口存在，多给一条探测路径 |
| 整体可用率口径 | 算术平均 | 加权需要流量数据，流量数据不对外 |
| 状态条形态 | 固定宽度竖条 | 等分铺满会压成细丝，看不出颜色 |
| 延迟指标 | 链路与响应分列 | 合并会让客户把上游生成时间算到网关头上 |
| 接口形态标签 | 外发 | 协议名不含厂商信息 |

## 10. 待扩展项

- 故障公告与历史事件：当前只有探测结果，没有人工发布的事件说明。
- 按分组聚合展示：监测项多时列表会长，可考虑折叠到分组维度。
- 订阅通知：状态变化时的邮件或 Webhook 推送。
