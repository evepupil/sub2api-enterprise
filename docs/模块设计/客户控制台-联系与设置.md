## 1. 职责与边界

联系我们页列出客服邮箱和 QQ 交流群，用户自己发邮件或进群；账户设置页（从头像菜单进入，用户确认保留）管理个人资料与登录安全，仍只改页内状态。

## 2. 结构与数据流

- 联系我们：客服邮箱 `support@codu.xyz` 与 QQ 群号都从站点配置读，各带复制按钮，邮箱点了直接写邮件；页脚的「联系我们」也改成写邮件到这个地址。
- 设置：个人资料（名称可改、邮箱只读已验证）、修改密码（三项校验）、两步验证（开启走扫码与 6 位验证码弹窗，关闭要确认）、绑定或解绑 Google。

## 3. 关键决策

- 不做工单系统（用户 2026-10-04 定：直接简单点，显示邮箱、QQ 群）：sub2api 后端没有工单，自建要加表、用户接口、管理端回复页和邮件通知。邮箱用域名邮箱 `support@codu.xyz`：在 Cloudflare 打开 codu.xyz 的邮件转发（自动加了收信 MX、发信验证 SPF 与 DKIM 记录），规则 support@codu.xyz → 运营者的 Gmail；Cloudflare 每条规则只能转一个邮箱，要改转 QQ 邮箱就在 Cloudflare 里改这条规则。
- 通道页「工单 N 小时内响应」改叫「客服 N 小时内响应」；占位公告「通过工单申请发票」改成联系我们，去掉「工单有新回复」那条占位通知。
- 两步验证的开关不直接切换，开启必须完成验证码确认，关闭必须二次确认。

## 4. 当前实现

- 联系我们页：窄版，一个面板两行（客服邮箱、QQ 交流群），每行图标、名称、内容（邮箱是写邮件的链接）、复制按钮。
- 账户设置：个人资料（名称可改、邮箱只读已验证，没改动时保存按钮禁用）、修改密码（三项校验）、两步验证（开启走扫码与 6 位动态码弹窗，关闭要确认）、绑定或解绑 Google。
- 联系我们 1 个文件、设置页 11 个文件；设置页的校验是纯函数（有单测）。

## 5. 验证方式

交互检查表见页面规格末尾。
