## 1. 职责与边界

联系我们页列出客服邮箱和 QQ 交流群，用户自己发邮件或进群；账户设置页（从头像菜单进入，用户确认保留）改名称、改登录密码，都提交给后台（2026-10-07 接通）。两步验证不做；第三方账号绑定等谷歌登录接好后再加。

## 2. 结构与数据流

- 联系我们：客服邮箱 `support@codu.xyz` 与 QQ 群号都从站点配置读，各带复制按钮，邮箱点了直接写邮件；页脚的「联系我们」也改成写邮件到这个地址。
- 设置：个人资料取当前登录账号（名称 = 后台用户名，可改；邮箱只读）。改名称 → 官网 `PUT /api/portal/console/account/profile` → 后台 `PUT /user { username }`，成功后把新名字合进登录状态（头像菜单立刻变）。改密码 → 官网 `PUT /api/portal/console/account/password` → 后台 `PUT /user/password { old_password, new_password }`；后台改完会让这个账号所有旧凭证失效，官网接口成功时清掉登录 cookie，页面提示后跳登录页。两个接口都只接受本站页面发起的请求，没登录回 401。

## 3. 关键决策

- 不做工单系统（用户 2026-10-04 定：直接简单点，显示邮箱、QQ 群）：sub2api 后端没有工单，自建要加表、用户接口、管理端回复页和邮件通知。邮箱用域名邮箱 `support@codu.xyz`：在 Cloudflare 打开 codu.xyz 的邮件转发（自动加了收信 MX、发信验证 SPF 与 DKIM 记录），规则 support@codu.xyz → 运营者的 Gmail；Cloudflare 每条规则只能转一个邮箱，要改转 QQ 邮箱就在 Cloudflare 里改这条规则。
- 通道页「工单 N 小时内响应」改叫「客服 N 小时内响应」；占位公告「通过工单申请发票」改成联系我们，去掉「工单有新回复」那条占位通知。
- 两步验证不做（2026-10-07 用户定：只用账号密码登录），设置页不给开关；某个账号在后台开过两步验证时，登录页照旧要第二步验证码（原来就接好了，不然这些账号登不进来）。
- 谷歌绑定的假操作撤掉（原来点一下就显示「已绑定」），等谷歌登录接好后按后台的绑定接口再加。
- 改密码成功后让用户重新登录：后台的设计就是改密码作废所有旧凭证，官网不偷偷用新密码再登一次（账号可能开着两步验证或人机验证），提示后跳登录页，登录后回到设置页。
- 新密码至少 6 位（和注册、找回密码、后台一致，原来的 8 位是页面自己定的）；名称最多 32 个字（后台上限 100，界面收紧避免撑破头像菜单）。

## 4. 当前实现

- 联系我们页：窄版，一个面板两行（客服邮箱、QQ 交流群），每行图标、名称、内容（邮箱是写邮件的链接）、复制按钮。
- 账户设置：个人资料（当前账号的名称可改、邮箱只读，没改动时保存按钮禁用，失败时按钮左边红字）、修改密码（三项校验 + 后台判定当前密码；成功后提示并跳登录页）。
- 联系我们 1 个文件、设置页 8 个文件，另有官网接口 2 个、后台对接 2 个、浏览器端 2 个文件；校验与提交内容检查都是纯函数（有单测）。

## 5. 验证方式

- 单测：`tests/console-pages.test.ts`（名称与密码校验，新密码至少 6 位）、`tests/console-account-route.test.ts`（提交内容检查；改名称转 `PUT /user`、回存下的名字；没登录 401、别的网站 403、内容不合法 400 都不调后台；后台 401 / 429 / 500 对应回 401 / 429 / 503；改密码转 `PUT /user/password`、成功后清掉登录 cookie，当前密码不对回 password_incorrect 且不清 cookie）。
- 浏览器实测见改动历史；交互检查表见页面规格末尾。

## 6. 待扩展项

- 以后要做工单系统时：后端加工单与对话两张表和用户接口，管理端加回复页，客服回复发邮件通知。
- 谷歌登录接好后，在设置页加回「第三方账号」：用后台的绑定、解绑接口。
