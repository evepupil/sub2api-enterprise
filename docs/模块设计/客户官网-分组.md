文件名、代码目录（`blocks/groups`、文案命名空间 `groups`）和数据里的 edition / personal / pro / enterprise 沿用旧名，页面上一律叫「通道」。

## 1. 职责与边界

版式照模板价格页，但本站不是订阅：月付年付切换去掉，套餐卡换成共享通道、专用通道、企业通道三张，通道名下面直接是说明（不写可用率承诺）。页面只讲权益差别，单价在价格页看，倍率不在官网展示。特权与额度为占位数据。

## 2. 结构与数据流

- 页首（标题 + 一句「每个密钥绑定一个通道」）→ 三张通道卡（共享通道、专用通道（重点卡）、企业通道）→ 三种通道 11 项特权对比表（专用通道整列高亮）→ 常见问题 5 条 → 厂商标志。
- 通道卡：名称下面直接是一句说明（2026-10-06 去掉了可用率目标大字）；清单 = 上一档全部特权（共享通道没有）→ 限额（企业通道写「按合同约定」）→ 客服响应时限 → 各通道独有的几条。
- 特权对比的可用率、限额、客服响应时限从通道数据推出，不另写一份；不含倍率行和渠道类型行。
- 倍率（共享 ×0.15、专用 ×0.3、企业定制）仍留在通道数据里，只供模型页、价格页算单价和控制台显示。

## 3. 关键决策

- 一个通道就是后端的一个分组：API 密钥绑定哪个分组，就用该通道的资源和价格。
- 2026-10-03 用户决定：菜单「分组」改叫「通道」，三档改名共享通道、专用通道、企业通道；通道页不显示倍率，只显示权益差异；卡片按钮「开始使用」改为「查看定价」。
- 页面地址从 `/groups` 改为 `/channels`。站点还没上线，旧地址不做跳转，直接 404。
- 对比表删掉「渠道类型」行：新名字本身就说明了资源差别，再写「共享渠道池 / 优选渠道 / 专属渠道」是重复，「渠道」和「通道」并存还容易混。
- 企业通道按钮是「联系客服」，发邮件给客服邮箱（2026-10-06 用户要求），模板 Enterprise 卡的「Contact Us」同理。
- 官网不写任何可用率承诺（目标、赔付、协议，2026-10-06 用户要求）；不支持对公转账，可以开发票但不是增值税发票。
- 多通道密钥（一个密钥绑多个分组）讨论后暂不做，常见问题里写的是现状：每个密钥绑定一个通道。

## 4. 当前实现

- 页首：标题「通道」与副标题，没有通道切换。
- 通道卡：三张等高卡，大屏三列、以下单列收窄居中；专用通道为深蓝渐变重点卡带「最常用」；说明、特权对勾列表、按钮靠底（共享通道「查看定价」去价格页，专用通道「查看定价」去价格页并带 `?edition=pro`，企业通道「联系客服」发邮件给客服）。
- 特权对比：11 行，专用通道整列高亮，对勾 / 横线附读屏文字；表下「查看价格」。
- 常见问题 5 条；底部厂商标志轮换。
- 整页都是服务端组件，不依赖网址里的通道参数。

## 5. 验证方式

- 单测 `tests/groups.test.ts`：三种通道的顺序、中英文名、倍率、重点卡与按钮类型（查看定价 / 联系客服）、独有特权、倍率写法、对比表 8 行且没有倍率、渠道类型、可用率、可用率赔付、对公转账与发票行。
- 交互检查表见页面规格末尾（三张卡、按钮去向、联系客服、对比表、旧地址 404）。
- 2026-10-03 在开发服务上逐页检查渲染结果：通道页、价格页、模型页、首页的中英文版本都没有残留「个人版 / 专业版 / 企业版 / 分组 / 倍率」字样；`/groups` 返回 404。

## 6. 待扩展项

- 通道与价格改读后端分组配置（一个通道对应一个或多个后端分组）；组织可用通道按平台授权显示。
