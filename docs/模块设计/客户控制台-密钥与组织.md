## 1. 职责与边界

密钥页管理调用凭证，每个密钥绑定一个分组，按分组倍率计费；2026-10-04 起接通后端，只管登录账号自己的密钥，创建、编辑的逻辑照 sub2api。组织页参照图里没有，是企业客户的核心需求（用户确认保留）；2026-10-04 起接通后端，能力照 sub2api 原来的组织管理，只给组织管理员（组织创建者）：管成员的名称、额度和启用状态，设新成员默认配额，审批配额申请，发组织邀请码。个人用户和普通成员看不到组织入口；普通成员的组织配额（剩余额度、申请额度、撤回申请）放在用量页（用户确认）。

## 2. 结构与数据流

- 密钥的取数：浏览器 → 官网接口 `/api/portal/console/keys?page&pageSize&search&status`（带着登录状态，凭证过期自动续期）→ 后端同时读三样：密钥列表 `/api/v1/keys`（后端分页、新建的在前，带完整密钥）、账号的专属倍率 `/groups/rates`、近 30 天按天按密钥的用量（用量总览接口，`dimensions=api_key`）。官网服务器把用量加总成「近 30 天」「今天」（北京时间），分组倍率换成专属倍率；倍率或用量读不到时照常给列表，用量写「—」。能选的分组另走 `/api/portal/console/keys/groups`（后端 `/groups/available` + `/groups/rates`）。
- 密钥的改动：创建 `POST /api/portal/console/keys` → 后端 `POST /keys`；编辑、暂停 / 启用、清零已用额度、清零限速用量 `PATCH /api/portal/console/keys/{id}` → 后端 `PUT /keys/{id}`；删除 `DELETE /api/portal/console/keys/{id}` → 后端 `DELETE /keys/{id}`。这三个都先看登录、只接受官网自己页面发起的请求、官网服务器再校验一遍，成功后页面重读列表。
- 页面：搜索（名称或密钥）+ 状态 → 表格（密钥打码可显示、复制；分组与倍率；状态；近 30 天与今日用量；额度进度；有效期；编辑、暂停 / 启用、删除）；创建成功后完整密钥在弹窗里显示一次（之后在列表里也能随时显示、复制）。
- 组织的取数：浏览器 → 官网接口 `/api/portal/console/organization*` → 后端 `/api/v1/organization*`（只认登录身份，每个接口都校验组织管理员）。打开页面同时读组织概况、申请设置、配额申请（默认只看待处理）、邀请码、新成员默认配额、成员（后端分页，可按邮箱或用户名搜索、按状态筛选）。
- 组织的改动：改成员 `PATCH /members/{userId}`（一次改一项：状态、名称、消费上限、周期配额，转成后端四个 PUT 之一）；批量 `POST /members/batch`（周期发放、平分上限）；默认配额、申请设置 `PUT`；处理申请 `POST /quota-requests/{id}`（通过、驳回、撤回）；邀请码 `POST /invitations`（只传有效天数）、`DELETE /invitations/{id}`（停用）。都先看登录、只接受本站页面发起的请求、官网服务器再校验一遍；成功后只重读受影响的区块，标题行「刷新」重读整页。
- 组织页：标题是组织名，右边刷新；上方左边是配额申请（状态筛选、申请设置、通过 / 驳回），右边是组织邀请码（有效期、创建、复制邀请码与邀请链接、停用）；下方是成员区（搜索、状态筛选、勾选后周期发放 / 平分上限，新成员默认配额一行，成员表）。组织被平台停用时最上面一条黄色提示。
- 普通成员：用量页最上面的「组织配额」卡片（`GET /api/portal/console/organization/my-quota`，后端在用户仪表盘统计里给 `organization_quota`，个人用户和组织管理员为空、不显示卡片）与最近 3 条申请（`GET /quota-requests`，成员只看到自己的）；申请 `POST /quota-requests`，撤回走处理申请接口。

## 3. 关键决策

- 创建、编辑照 sub2api 的密钥表单（2026-10-04 用户要求，列表的列沿用原来的）：名称、分组必填；自定义密钥、IP 限制（白名单 / 黑名单）、限速（5 小时 / 1 天 / 7 天最多花多少美元）、有效期（7 / 30 / 90 天或自选到期日）用开关打开；额度不填表示不限。编辑能换分组（用户确认，和 sub2api 一样）、能清零已用额度和限速用量；自定义密钥只能在创建时设。
- 校验规则照后端：名称最长 100 字节；自定义密钥 16–128 位，只能用字母、数字、下划线、连字符；IP 一行一个、最多 100 条；金额不能为负、最多 100 万；有效期最长 10 年。浏览器和官网服务器各校验一遍，后端的错误（自定义密钥已被占用、IP 格式不对、不能用这个分组等）按原因写成一句话。
- 状态照后端四种：启用、已暂停、额度用完、已过期（用户确认）。暂停 / 启用只在前两种之间切换；额度用完、已过期的要在编辑里加额度、清零已用额度或延期，后端会自动恢复启用。
- 有效期：新建时把到期日换成「多少天后到期」（后端接口只收天数）；编辑时到期时刻写成那天结束（北京时间 23:59:59），而且只在改过时才提交，免得把原来的到期时刻改掉。
- 列表要显示、复制完整密钥，所以官网接口会把账号自己的完整密钥交给浏览器（和 sub2api 一样）；日志页依然不传密钥。
- 能选的分组只列账号能用的（组织成员只有组织授权的，由后端判断）；只有一个分组时直接选上，多个时要自己选。
- 分组下拉照原版 sub2api 选分组的样子（2026-10-08 用户要求）：每项左边是分组名（加粗）和后台写的分组描述（保留换行，最多三行，悬停看全文；没写不显示），右边是倍率——账号有专属倍率时先写划掉的分组原倍率、再写专属倍率（~~×0.305~~ ×0.3），分组开了高峰加价时再写「高峰 20:00–23:00 ×1.5」（手机宽度下这个标签放到描述下面，不把描述挤成一条）；选好后框里只写分组名与倍率。倍率沿用控制台的「×0.3」写法。分组描述只在控制台显示，官网价格页不显示（用户定，描述里可能有写给老用户的话）；换分组仍要点「编辑」，不做列表里点分组直接换（用户定）。
- 组织页只给组织管理员（2026-10-04 用户确认，和 sub2api 的用户菜单一致）：侧栏的「组织」只在当前用户是组织创建者时显示；个人用户、普通成员直接打开地址会回到用量页；普通成员的组织配额与申请放在用量页。
- 去掉占位时的数字卡、移除成员、角色列、密钥数、复制组织 ID（2026-10-04 用户要求）：后端没有这些能力或用不上。
- 成员额度三种方式照 sub2api：不限额、固定累计上限（可以填 0，不让这个成员消费）、周期配额（每期金额 + 周期天数，立即生效或指定北京时间生效；生效前沿用原来的上限）。不限额、固定上限走后端的消费上限接口，后端会顺带清掉周期配额，弹窗里提前写明。
- 批量：勾选跨页保留；周期发放给勾选的人统一发同一份周期配额；平分上限把总额按人数平分成固定累计上限，提交前列出每人分到多少（和后端一样以 1e-8 为单位，零头补给 ID 小的成员）。组织管理员本人不能勾选、不能设额度、不能停用，只能改名。
- 新成员默认配额：开启时可以顺带发给没配周期配额的成员（默认勾上）、覆盖已配过的成员（默认不勾）；关闭要确认。
- 配额申请：方式照后端三种（关闭、先审批再加、申请了就加），不关闭时要设单次最低、最高；通过要确认（会给成员加额度），驳回可写备注（最多 500 字）；通过时成员已经不能加额度（改成不限额或被停用），后端会把申请自动作废，页面写清楚。
- 邀请码：有效期 1 / 7 / 30 天或长期，页面只传天数，到期时间由官网服务器按当前时间算；过了有效期但后端还记「有效」的显示「已过期」；邀请链接是官网注册页 `/register?invitation_code=…`（和 sub2api 一样，注册页认这个参数）；只有还能用的邀请码是绿色徽标。

## 4. 当前实现

- 密钥页（真实数据）：标题行是刷新与创建密钥；搜索（停 300 毫秒才查）与状态筛选交给后端，后端分页；表格 1100 宽，操作列固定；密钥默认打码，可显示完整密钥与复制；分组用分组倍率徽标；额度有进度条；首次加载显示占位块，换条件时旧数据变浅，读不到时显示「重试」；行上操作失败时表格上方红字；创建、编辑弹窗按上面的规则，出错时所有错项一起标红、焦点落到第一项；清零要先确认；删除要确认。
- 组织页（真实数据）：标题是组织名；配额申请区（默认看待处理，可切全部、已发放、已驳回、已撤回；没开申请时写「组织没有开配额申请」；每条写申请人、金额、理由、时间、状态与审批备注；每页 10 条）与组织邀请码区（列表太长时在区块里滚动）宽屏左右并排；成员表 960 宽、操作列固定，列为勾选、名称、邮箱与用户名、状态、额度（固定上限或「每 N 天」，指定时间生效的标「待生效」）、已消费、剩余额度（周期配额写下次重置时间，有冻结金额也写，用完变黄）、操作（改名、设置配额、停用 / 启用，停用要确认）；首次加载显示占位块，换条件时旧数据变浅，读不到时显示「重试」，行上操作失败时在所在区块写一句话。
- 用量页的组织配额卡片（普通成员）：剩余额度（不限额时写不限额）与下次重置时间；能申请时右上角「申请额度」，有一条在等处理时换成「申请处理中」；下面列最近 3 条申请（金额、状态、时间、审批备注或理由），待处理的可以撤回；申请弹窗写单次可申请的范围，超出范围时报错直接写范围。
- 密钥页 11 个文件、组织页 13 个文件、用量页的组织配额卡片 2 个文件；密钥的表单规则（`keys-model.ts`）、输入规则（`keys-rules.ts`）、官网服务器的转换与校验（`api-keys.ts`），组织的表单规则（`organization-model.ts`）、输入规则（`org-rules.ts`）、官网服务器的转换与校验（`organization.ts`）都是纯函数（有单测）。
