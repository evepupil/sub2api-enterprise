# 官方同步与升级

## 1. 职责与边界

- 将官方主线完整合入当前主分支，保留双方提交历史。
- 保留组织注册、成员配额、组织代付、分组授权、ACF 接口、独立官网和控制台，以及直连入口与备份配置。
- 修复请求开始后删除密钥导致整笔结算回滚的问题。
- 历史漏扣不自动补扣，已禁用账号和关闭注册的线上设置不自动恢复。

## 2. 结构与数据流

- 合并前版本：`d2a92daa4e0acb5f22f7ba1cb87dbc7937d1574c`，回退引用 `backup/pre-upstream-sync-20261115`。
- 官方仓库：`https://github.com/Wei-Shaw/sub2api`，目标 `530c5e3a4f9c73ca2b0881191d0ef8e0d82c5484`；对应 v0.2.21，之后仅版本标识和赞助信息调整。
- 共同基线：`98d86915becae9fe9491a91ffc6defd5235c8d2b`；本方 205 个独有提交，官方 1262 个待合入提交。
- 试合并发现 50 个冲突文件，主要涉及认证、公共设置、计费后处理、后台界面及生成代码。
- 计费仍在同一笔事务内完成余额或订阅结算、组织消费累计、账号额度和请求去重。密钥删除只使密钥自身的计数更新失去意义，不能撤销用户已经产生的消费。

## 3. 关键决策

- 使用正常合并保留历史，不覆盖为纯官方仓库，也不改写已有提交。
- 使用官方 PR #7816 的删除密钥结算规则；真实数据库故障仍返回错误。
- 冲突按行为合并：官方新增能力与企业定制均保留，已有界面继续使用本项目主题。
- 已执行迁移文件保持文件名和内容不变。迁移按完整文件名追踪，编号重叠本身不构成重复执行依据。
- 验证空库初始化和已有数据库升级，不能用其中一项代替另一项。
- Windows 运行依赖安装、检查、测试和构建；WSL 仅承担 Docker 容器与最终 Linux 镜像构建。

## 4. 当前实现

- 官方目标的全量代码已进入合并结果，50 处文本冲突已处理；组织定制、独立门户和入口配置保留。
- 删除密钥后，余额、订阅和组织代付继续结算；密钥自身的额度与窗口计数跳过，重复结算仍受请求去重保护。
- 官方费用预留接入组织付款人，固定费用按成员剩余额度检查；开启在途预留时，把同成员其他未结算费用也计入准入。
- 余额通知继续使用官方的有界后台队列，在后台读取实际付款人的通知配置，避免被成员自己的开关提前跳过。
- 视频端点的批量能力设置与单账号配置保持一致，补齐后端对 Seedance 的校验。
- 重新生成 Ent 与 Wire，使用 Go 1.27.3；开发指南与官方 CI 的 golangci-lint 2.14.0 保持一致。
- Windows 测试用目录联接覆盖路径逃逸场景；时间断言考虑毫秒精度，内存分配断言在独立进程执行并保留原上限。用户仓储测试按完整外键关系清理隔离数据，清理错误不再被忽略。缓存测试隔离无关后台工作线程，每个模拟通道场景使用独立缓存标识，避免粗粒度时钟造成测试数据碰撞。
- 生产已有的 293 个迁移内容校验全部一致。真实数据库备份恢复到本机隔离库后，18 个新增迁移执行成功，总数 311；52 个用户及金融、组织数据摘要保持一致，再次执行迁移也通过。
- 仓库同步与本地验证已完成；生产版本尚未切换，历史漏扣未补扣。

- 数据库：旧迁移校验不变，空库执行完整迁移，生产库副本执行新增迁移。
- 后端：单测、集成测试、静态检查和服务构建。
- 管理前端：依赖锁定安装、静态检查、类型检查、核心测试与构建。
