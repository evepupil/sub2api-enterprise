# Sub2API Enterprise 需求设计

版本：0.1.0

更新日期：2026-09-10

阶段：M1 最小需求确认稿，功能尚未实现

## 1. 产品目标

在 Sub2API 的现有用户平台上增量增加组织能力，为个人用户和小型企业提供统一的模型 API 服务。

M1 优先跑通注册、创建或加入组织、管理成员、分配消费配额、使用授权分组以及查看组织用量。尽量沿用现有界面和业务行为。

整体专业化视觉与首屏改造安排在 M2。ACF 安全能力和 ManyRouter 供应优化分别作为 M3、M4 的后续方向。

## 2. 用户与组织

### 2.1 四种用户角色

| 角色 | 定位 | 主要能力 |
|---|---|---|
| 管理员 | 现有平台管理员 | 保留全平台管理能力，新增管理组织和配置组织分组范围 |
| 用户 | 现有个人用户 | 沿用个人充值、密钥、分组和使用记录等功能 |
| 组织管理员 | 组织创建者 | 使用本人账号余额承担组织消费，管理本组织成员、邀请码和消费配额，查看全组织用量 |
| 组织用户 | 通过组织邀请加入的普通成员 | 创建和管理自己的密钥，在个人配额和组织授权范围内使用服务，查看自己的用量 |

- 一个账号最多属于一个组织，个人用户不属于组织。
- 每个组织只有一个组织管理员，由创建者担任。
- 组织管理员仍属于企业客户，权限仅覆盖自己的组织。
- M1 不提供新增组织管理员、管理员转让、组织切换或跨组织成员转移。
- 现有管理员和个人用户保持原有身份与业务行为。

### 2.2 组织信息

M1 组织只需具有名称、创建者、成员关系、可用分组范围和创建时间。成员消费由创建者的账号统一结算。

## 3. 注册与邀请码

### 3.1 两个现有开关共同生效

保留系统设置中的“开放注册”和“邀请码注册”两个开关，不增加组织专用注册开关。

| 开放注册 | 邀请码注册 | 个人注册 | 创建组织 | 加入已有组织 |
|---|---|---|---|---|
| 关闭 | 任意 | 不允许 | 不允许 | 不允许注册新成员 |
| 开启 | 关闭 | 可直接注册 | 可直接创建 | 通过组织邀请码确定加入的组织 |
| 开启 | 开启 | 使用平台邀请码 | 使用平台邀请码 | 使用组织邀请码 |

关闭邀请码注册时，取消的是平台注册资格限制。加入已有组织仍通过组织邀请码确定归属，不能自行选择任意组织加入。

两个开关对各注册入口一致生效。已有账号仍可按现有规则登录和使用服务。

### 3.2 注册界面与流程

- 注册界面提供一个邀请码输入框，接受平台邀请码或组织邀请码，系统自动识别类型。
- 不要求用户同时填写两种邀请码。
- 邀请码输入区域下方提供“创建组织”文字入口；关闭邀请码限制时，该入口仍可用。
- 普通注册使用平台邀请码时，创建个人用户；无需邀请码时，普通注册直接创建个人用户。
- 使用组织邀请码时，创建组织用户并加入邀请码对应的组织。
- 通过“创建组织”入口补充组织名称，完成注册后创建组织，并将注册人设为唯一组织管理员。
- 开启邀请码注册时，创建组织需要平台邀请码；组织邀请码只用于加入其绑定的组织。
- 邮箱验证、密码要求以及其他已有注册校验继续遵循现有设置。

### 3.3 邀请码管理

- 平台管理员通过现有功能管理平台邀请码。
- 组织管理员可以创建本组织的邀请码，供新成员注册加入。
- 组织邀请码只能用于其绑定的组织，只能创建普通组织用户。
- 不单独设置组织邀请码开关，其使用遵循上述统一注册规则。
- 邀请码有效性和使用限制尽量沿用现有机制，具体支持方式在模块设计时核对。

## 4. 平台组织管理

平台管理员界面新增“组织管理”菜单页。

M1 支持：

- 查看全平台组织列表及组织详情，包括名称、组织管理员和成员信息。
- 为每个组织设置可使用的分组范围。
- 从组织详情查看该组织成员，沿用平台已有用户管理能力。

组织管理员和组织用户不能访问全平台组织管理功能。

## 5. 组织成员管理

组织管理员拥有“成员管理”入口。该页面沿用现有用户管理的列表和操作方式，可见及可操作对象限定为当前组织成员。

- 查看、查询本组织成员及其配额和用量。
- 启用、禁用本组织普通成员，行为与现有用户管理一致。
- 为成员设置和调整消费配额，支持批量均分。
- 创建组织邀请码邀请新成员。
- 不提供将普通成员提升为组织管理员或平台管理员的操作。

成员禁用只执行现有账号禁用行为。配额记录、组织归属和历史消费保留；不额外清空配额、转移余额或删除密钥。恢复账号后继续遵循现有启用规则及该成员的配额限制。

## 6. 分组权限

- 平台管理员在“组织管理”中统一设置组织可用分组。
- 组织管理员和普通成员默认拥有该组织全部已授权分组。
- 成员创建密钥时，从组织授权分组中选择，沿用现有密钥分组选择方式。
- M1 不新增组织管理员逐人二次分配分组的流程。
- 组织管理员不能扩大平台授予组织的分组范围，也不能管理平台线路或修改分组价格。
- 组织分组授权调整后，分组选择和已有密钥调用均遵循调整后的范围。
- 个人用户继续沿用现有个人分组权限规则。

## 7. 余额与消费配额

### 7.1 资金归属与扣费

- 组织充值由组织管理员完成，资金进入其现有账号余额。
- 组织管理员给普通成员分配消费配额，配额表示该成员最多可以消费的金额。
- 分配或调整配额不发生真实余额转账。
- 普通成员的实际消费统一扣组织管理员账号余额，同时累计该成员已使用的配额。
- 同一成员使用多个密钥时，消费共同计入该成员的配额。
- 组织管理员自己的密钥继续使用其账号余额，消费仍记在管理员本人名下。
- 密钥已有的额度、有效期及其他调用限制继续有效。
- 个人用户继续从本人账号余额扣费。

例如：组织管理员余额为 1000，给成员甲分配 300 配额。成员甲使用自己创建的密钥消费 10 后，管理员余额为 990，成员甲已用配额为 10，剩余配额为 290。

分配配额不会预留一笔专属资金。组织管理员余额也会被本人或其他成员消耗，成员实际能否继续调用同时受结算账号余额、本人剩余配额以及密钥现有限制约束。

### 7.2 配额管理

- 组织管理员可以查看成员的分配配额、已用配额和剩余配额。
- 支持单人调整和选中多个成员后的“均分”操作。
- 均分将管理员指定的分配金额等额分配给选中成员，用于减少逐个操作。
- 配额调整及均分保留已发生的消费记录，不修改真实余额。
- 成员停用不会自动回收、清空或重新分配其配额。

配额的保存方式、与现有额度机制的对应方式、均分计算细节和并发扣费处理，在后续模块设计阶段深入核对源码。本需求文档只约定用户能够完成的操作及资金和用量的归属。

## 8. API 密钥

API 密钥界面与归属行为保持现状：

- 普通成员可以自行创建和管理密钥。
- 组织管理员创建的密钥继续挂在管理员名下，可以直接交给他人使用。
- 使用某个密钥产生的记录归该密钥所属用户，不能由此识别实际持有人。
- 不增加“共享密钥”类型、改名或解释文案。

M1 在调用时落实组织分组范围、成员配额和组织结算规则，不要求增加新的密钥操作流程。

## 9. 使用记录与统计

- 个人用户和普通组织成员继续查看自己的使用记录。
- 组织管理员可以查看本组织全体成员的使用记录，包括管理员本人。
- 组织使用记录支持按成员筛选，其余筛选与展示沿用现有使用记录页面。
- 统计区域增加“成员分布”，按当前统计时间范围内的组织成员用量展示；指标口径沿用现有分布统计。
- 成员分布按密钥所属用户统计，管理员交给其他人使用的密钥仍归管理员本人。
- 不额外创建“组织共享”统计项。
- 历史记录保留产生时的组织归属，禁用成员不会让其历史用量从组织统计中消失。
- 组织范围同时适用于记录列表、详情、筛选和统计结果。

## 10. 阶段范围

| 阶段 | 目标 | 当前边界 |
|---|---|---|
| M1 | 跑通个人与企业注册、单组织、成员、消费配额、分组授权和组织用量 | 当前最小需求；界面沿用现有风格和组件 |
| M2 | 改造整体风格、首屏和控制台体验，使产品更专业 | 后续单独讨论视觉与交互需求 |
| M3 | 接入 ACF 安全增强能力 | 后续讨论中间件及控制台整合需求 |
| M4 | 接入 ManyRouter 供应与线路能力 | 后续讨论数据和管理能力整合需求 |

上述阶段划分记录本次需求范围，正式路线图在需求、技术和架构讨论完成后建立。当前不将任何功能阶段标记为已完成。

M1 不包含多组织身份、多个组织管理员、自定义角色、部门或项目层级、管理员转让、成员跨组织迁移、ACF 或 ManyRouter 接入，以及全站视觉重做。

## 11. M1 验收要求

1. 关闭开放注册后，个人注册、创建组织和通过组织邀请注册均被拒绝；已有用户仍可登录。
2. 开放注册且关闭邀请码注册时，个人和组织创建者均可直接注册。
3. 开放注册且开启邀请码注册时，平台邀请码和组织邀请码均可独立完成对应注册，不能无邀请码注册。
4. 创建组织后，创建者成为唯一组织管理员；通过组织邀请注册的人只能成为该组织普通成员。
5. 平台管理员可以查看组织并配置其分组范围，组织成员默认获得该组织全部授权分组。
6. 组织成员无法使用组织未获授权的分组，已有密钥同样受最新授权约束。
7. 组织管理员只管理本组织成员，无法通过修改请求中的对象访问其他组织的数据或操作其他用户。
8. 成员禁用、恢复行为与现有用户管理一致，配额和历史记录保留。
9. 成员消费正确扣组织管理员账号余额，并累计该成员配额；多个密钥共同受该成员配额限制。
10. 调整和均分配额不转移真实资金、不抹除历史消费；结算账号余额或成员配额不足时，调用受到限制。
11. 组织管理员可查看全组织使用记录及成员分布，普通成员只查看本人记录。
12. 管理员创建并交给他人使用的密钥保持现有名称和归属，其用量计入管理员本人。
13. 个人用户原有充值、密钥、分组与使用记录功能保持可用。
