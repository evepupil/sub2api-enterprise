## K API 密钥 `src/blocks/console/keys/keys-page.tsx`（导出 `KeysPage`，拆成 `keys-*.tsx`）

2026-10-04 起接后端（技术设计 18.6）：列表、创建、修改、删除都走官网接口 `/api/portal/console/keys*`，再到后端 `/api/v1/keys`。创建、编辑照 sub2api 的密钥表单（用户要求），列表的列沿用原来的。

**外层**：`<ConsolePage id="keys" title={t('meta.title')} actions={<RefreshButton onRefresh={重取} /> + 创建密钥（primary，Plus 图标，data-create-key；北京时间的今天读到之前不可点）}>`。

**页内状态**：`searchText`（输入框原文，停 300ms 后才当条件，`useDebouncedValue`）、`status: KeyStatus | 'all'`、`page`、`pageSize`、`reloadKey`（刷新：列表和分组都重取）、`version`（改动成功后只重取列表）、`revealed: Set<number>`（显示完整密钥的行）、`busy: Set<number>`（正在暂停 / 启用 / 删除的行）、当前弹窗、`actionError`（行上操作失败的原因）。

**数据**：`useLoadable`（`src/lib/console/live/loadable.ts`）取两份：一页密钥 `fetchKeys({ page, pageSize, search, status })`（带完整密钥、每把密钥近 30 天与今天的用量）、能选的分组 `fetchKeyGroups()`。换条件时旧数据变浅（`opacity-60`、`aria-busy`）；首次加载占位块（`data-keys-loading`）；读不到时 `<EmptyState id="keys-error" icon={TriangleAlert}>`「密钥暂时加载不出来」（太频繁时「查询太频繁，请稍后再试」）+「重试」（`data-keys-retry`）。

### K1 筛选

`flex flex-col gap-3 sm:flex-row sm:items-center`：`<SearchInput id="key-search" data-key-search placeholder="搜索名称或密钥" className="sm:w-72" />` + `<Select name="key-status" className="sm:w-40">`：全部状态 / 启用 / 已暂停 / 额度用完 / 已过期。搜索和状态交给后端，换条件回到第 1 页。行上操作失败时下面一行红字（`role="alert"`，`data-key-error={原因}`）。

### K2 密钥表

`<TableShell id="keys" footer={<Pagination />}>`（页码、总数由后端给）→ `<Table minWidth={1100}>`，每行 `data-key-row={ID}`，列：

| 列 | 内容 |
|---|---|
| 名称 | 名称（`font-medium truncate max-w-48`）+ 下一行「创建于 {北京时间日期}」`text-xs text-subtle-foreground` |
| 密钥 | `font-mono text-xs`：默认 `maskKey(secret)`，显示时完整密钥（`break-all`）；后面 `Eye` / `EyeOff` 图标按钮（`data-reveal={ID}`，`aria-label` 显示密钥 / 隐藏密钥）和 `CopyButton name="key-secret"`（复制完整密钥） |
| 分组 | 共享组件 `<GroupWithRate>`：分组名 + 倍率徽标（账号有专属倍率时用专属倍率）；没有分组写「未分组」 |
| 状态 | 启用 `success`；已暂停 `warning`；额度用完 `danger`；已过期 `neutral`；`data-key-status={active / inactive / quota_exhausted / expired}` |
| 用量 | 两行小字：「近 30 天 {次数} 次 · {金额}」「今日 {次数} 次 · {金额}」（北京时间，后端用量总览按天按密钥加总）；用量读不到时「—」 |
| 额度 | 不限（额度为 0）：`Infinity` 图标 +「不限」；有上限：「{已用} / {上限}」+ 下面一条 `h-1.5 rounded-full bg-muted` 的进度条（满了 `bg-danger-graphic`，否则 `bg-primary`） |
| 有效期 | 「永久」或到期日（北京时间）；已过期的 `text-danger` |
| 操作（`sticky="right"`） | 「接入」小按钮（secondary，`Terminal` 图标，`data-key-usage={ID}`）；编辑（`Pencil`，`data-key-edit`）；暂停 / 启用（`Pause` / `Play`，`data-key-toggle`，只在启用、已暂停之间切换，额度用完和已过期的不可点：去编辑里加额度、清零已用额度或延期，后端会自动恢复启用）；删除（`Trash2`，`data-key-delete`）。操作进行中的那一行按钮先不可点 |

**空状态**：一把密钥都没有（也没筛选）：`<EmptyState id="keys" icon={KeyRound} title="还没有 API 密钥" action={创建密钥} />`；筛选没结果：标题「没有符合条件的密钥」，操作「清除筛选」。

### K3 创建密钥弹窗 `<Dialog id="create-key" title="创建 API 密钥" initialFocus="key-name">`

表单项照 sub2api（`keys-form-fields.tsx`），提交时所有出错的项一起标红，焦点落到第一个出错的项：

- 名称 `id="key-name"`：必填，最长 100 字节（后端字段上限，中文 33 个字）；错误「请输入名称」/「名称太长了」。
- 分组 `<Select name="key-group">`：只列账号能用的分组（组织成员只有组织授权的），每项是 `<GroupWithRate>`；没选时第一项是「请选择分组」，只有一个分组时直接选上；错误「请选择分组」；分组读不到时红字「分组暂时加载不出来，请稍后再试」。
- 自定义密钥：标签行右边 `<Switch id="key-custom-switch">`；打开后输入框 `id="key-custom"`（`font-mono`），16–128 位，只能用字母、数字、下划线、连字符；提示同规则，错误「请输入自定义密钥」/「至少 16 位」/「最多 128 位」/「只能用字母、数字、下划线和连字符」。
- IP 限制：`<Switch id="key-ip-switch">`；打开后白名单 `id="key-ip-allow"`、黑名单 `id="key-ip-block"` 两个多行框（`sm:grid-cols-2`，`font-mono text-xs`），一行一个 IP 或网段，最多 100 条；提示「一行一个 IP 或网段，如 203.0.113.5、10.0.0.0/8」；错误「有一行不是 IP 或网段，或者超过 100 条」。
- 额度（US$）`id="key-quota"`：前缀 `$`，0–1000000，提示「不填或填 0 表示不限」。
- 限速：`<Switch id="key-rate-switch">`；打开后三个金额框并排：5 小时 `id="key-rate-5h"`、1 天 `key-rate-1d`、7 天 `key-rate-7d`；提示「这段时间内最多花多少美元，0 表示不限」。
- 有效期：`<Switch id="key-expiry-switch">`；打开后 `<SegmentedControl name="key-expiry-preset">` 7 天 / 30 天 / 90 天 / 自选，下面到期日 `<Input type="date" id="key-expiry-date">`（默认 30 天后；新建要晚于今天，最长 10 年）；提示「到期日当天结束后失效」。提交时换成「多少天后到期」。

底部：取消 + 创建（`data-create-submit`，提交中是加载态）。后端失败时表单最后一行红字（`role="alert"`，`data-key-error`）：自定义密钥已被占用、IP 名单里有认不出的地址、账号不能用这个分组、操作太频繁、没有成功。成功后弹窗内容换成「密钥已创建」+ 完整密钥代码框（`data-new-key-secret`）+ `CopyButton name="new-key"` +「完成」（`data-create-done`）；关掉弹窗时列表重新读取。

### K4 编辑弹窗 `<Dialog id="edit-key" title="编辑密钥">`

同创建的各项，去掉自定义密钥；分组可以换（和 sub2api 一样），现在的分组不在可选列表里时也照样列出来。设了额度时额度框下面一条「已用 {已用} / {上限}」+「重置已用额度」；设了限速时每个金额框下面「已用 {金额}」，右下「重置限速用量」。重置要先确认（`<ConfirmDialog id="reset-key-usage" tone="default">`，标题「把已用额度清零？」/「把限速用量清零？」，确认「清零」），确认后马上生效、不用点保存。有效期：不早于今天；只在改过时才提交（到期时刻写成那天 23:59:59 北京时间），关掉开关就是改成永久。保存成功后关弹窗、列表重新读取；失败时表单最后一行红字。

### K5 接入示例弹窗 `<Dialog id="key-usage" size="lg" title="接入 {密钥名}">`

`<SegmentedControl name="key-snippet">`：Claude Code / Codex CLI / curl；下面一个代码框（`pre`，`bg-muted rounded-xl p-4 font-mono text-xs overflow-x-auto`）+ `CopyButton name="key-snippet"`。代码里的地址用 `SITE.apiBase`，密钥用该行完整密钥：

- Claude Code：`export ANTHROPIC_BASE_URL={apiBase}` / `export ANTHROPIC_AUTH_TOKEN={key}` / `claude`
- Codex CLI：`~/.codex/config.toml` 里 `model_provider = "codu"` 与 `[model_providers.codu]` 的 `name`、`base_url = "{apiBase}/v1"`、`env_key = "CODU_API_KEY"`，再一行 `export CODU_API_KEY={key}`
- curl：`curl {apiBase}/v1/chat/completions -H "Authorization: Bearer {key}" -H "Content-Type: application/json" -d '{"model":"gpt-6-sol","messages":[{"role":"user","content":"Hello"}]}'`

## 本页交互检查会找的东西

| 页面 | 操作 | 断言 |
|---|---|---|
| 密钥（需后端，本机测试账号） | 打开 `/console/keys` | 表头依次是名称、密钥、分组、状态、用量、额度、有效期、操作；「开发调试」一行的用量含「近 30 天 84 次」，分组格是「标准通道 ×0.15」 |
| 密钥（需后端） | 点 `[data-reveal]` | 第一行密钥格从打码变成完整密钥 |
| 密钥（需后端） | 点 `[data-create-key]` 后直接点 `[data-create-submit]` | 弹窗里 `[role="alert"]` 有「请输入名称」「请选择分组」 |
| 密钥（需后端） | 填名称、选分组、打开 `#key-custom-switch` 填 `short` 后提交 | 出现「至少 16 位」 |
| 密钥（需后端） | 自定义密钥改成 16 位以上、额度填 5、打开限速填 5 小时 1、打开有效期后提交，再点 `[data-create-done]` | `[data-new-key-secret]` 等于填的自定义密钥；表里多一行，额度「US$0.00 / US$5.00」，有效期是 30 天后 |
| 密钥（需后端） | 用同一个自定义密钥再建一次 | `[data-key-error]` 是「这个自定义密钥已被占用，换一个试试」 |
| 密钥（需后端） | 编辑刚建的密钥：改名、额度改 10、点「重置已用额度」并确认、到期日改成自选日期后保存 | 该行名称、额度「US$0.00 / US$10.00」、有效期都跟着变 |
| 密钥（需后端） | 点该行 `[data-key-toggle]` 两次 | `[data-key-status]` 先变 `inactive`、再变 `active` |
| 密钥（需后端） | 状态选「已过期」 | 出现「没有符合条件的密钥」与「清除筛选」 |
| 密钥（需后端） | 点该行 `[data-key-delete]` 再点 `[data-confirm]` | 这一行没了 |
| 密钥（手机宽度） | 打开创建弹窗、打开所有开关 | 弹窗左右在屏幕内，页面不横向溢出 |
| 组织 | 打开 `/console/organization` | `[data-member-row]` 有 5 行；`[data-stat="members"] [data-stat-value]` 为 `4/5` |
| 组织 | 点 `[data-invite-member]` → `[data-invite-generate]` | `[data-invitation-row]` 变 4 行 |
