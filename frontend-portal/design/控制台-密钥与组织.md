## K API 密钥 `src/blocks/console/keys/keys-page.tsx`（导出 `KeysPage`，拆成 `keys-*.tsx`）

2026-10-04 起接后端（技术设计 18.6）：列表、创建、修改、删除都走官网接口 `/api/portal/console/keys*`，再到后端 `/api/v1/keys`。创建、编辑照 sub2api 的密钥表单（用户要求），列表的列沿用原来的。

**外层**：`<ConsolePage id="keys" title={t('meta.title')} actions={<RefreshButton onRefresh={重取} /> + 创建密钥（primary，Plus 图标，data-create-key；北京时间的今天读到之前不可点）}>`。

**页内状态**：`searchText`（输入框原文，停 300ms 后才当条件，`useDebouncedValue`）、`status: KeyStatus | 'all'`、`page`、`pageSize`、`reloadKey`（刷新：列表和分组都重取）、`version`（改动成功后只重取列表）、`revealed: Set<number>`（显示完整密钥的行）、`busy: Set<number>`（正在暂停 / 启用 / 删除的行）、当前弹窗、`actionError`（行上操作失败的原因）。

**数据**：`useLoadable`（`src/lib/console/live/loadable.ts`）取两份：一页密钥 `fetchKeys({ page, pageSize, search, status })`（带完整密钥、每把密钥近 30 天与今天的用量）、能选的分组 `fetchKeyGroups()`。换条件时旧数据变浅（`opacity-60`、`aria-busy`）；首次加载占位块（`data-keys-loading`）；读不到时 `<EmptyState id="keys-error" icon={TriangleAlert}>`「密钥暂时加载不出来」（太频繁时「查询太频繁，请稍后再试」）+「重试」（`data-keys-retry`）。

### K1 筛选

`flex flex-col gap-3 sm:flex-row sm:items-center`：`<SearchInput id="key-search" data-key-search placeholder="搜索名称或密钥" className="sm:w-72" />` + `<Select name="key-status" className="sm:w-40">`：全部状态 / 启用 / 已暂停 / 额度用完 / 已过期。搜索和状态交给后端，换条件回到第 1 页。行上操作失败时下面一行红字（`role="alert"`，`data-key-error={原因}`）。

### K2 密钥表

`<TableShell id="keys" footer={<Pagination />}>`（页码、总数由后端给）→ `<Table minWidth={1020}>`，每行 `data-key-row={ID}`，列：

| 列 | 内容 |
|---|---|
| 名称 | 名称（`font-medium truncate max-w-48`）+ 下一行「创建于 {北京时间日期}」`text-xs text-subtle-foreground` |
| 密钥 | `font-mono text-xs`：默认 `maskKey(secret)`，显示时完整密钥（`break-all`）；后面 `Eye` / `EyeOff` 图标按钮（`data-reveal={ID}`，`aria-label` 显示密钥 / 隐藏密钥）和 `CopyButton name="key-secret"`（复制完整密钥） |
| 分组 | 共享组件 `<GroupWithRate>`：分组名 + 倍率徽标（账号有专属倍率时用专属倍率）；没有分组写「未分组」 |
| 状态 | 启用 `success`；已暂停 `warning`；额度用完 `danger`；已过期 `neutral`；`data-key-status={active / inactive / quota_exhausted / expired}` |
| 用量 | 两行小字：「近 30 天 {次数} 次 · {金额}」「今日 {次数} 次 · {金额}」（北京时间，后端用量总览按天按密钥加总）；用量读不到时「—」 |
| 额度 | 不限（额度为 0）：`Infinity` 图标 +「不限」；有上限：「{已用} / {上限}」+ 下面一条 `h-1.5 rounded-full bg-muted` 的进度条（满了 `bg-danger-graphic`，否则 `bg-primary`） |
| 有效期 | 「永久」或到期日（北京时间）；已过期的 `text-danger` |
| 操作（`sticky="right"`） | 编辑（`Pencil`，`data-key-edit`）；暂停 / 启用（`Pause` / `Play`，`data-key-toggle`，只在启用、已暂停之间切换，额度用完和已过期的不可点：去编辑里加额度、清零已用额度或延期，后端会自动恢复启用）；删除（`Trash2`，`data-key-delete`）。操作进行中的那一行按钮先不可点 |

**空状态**：一把密钥都没有（也没筛选）：`<EmptyState id="keys" icon={KeyRound} title="还没有 API 密钥" action={创建密钥} />`；筛选没结果：标题「没有符合条件的密钥」，操作「清除筛选」。

### K3 创建密钥弹窗 `<Dialog id="create-key" title="创建 API 密钥" initialFocus="key-name">`

表单项照 sub2api（`keys-form-fields.tsx`），提交时所有出错的项一起标红，焦点落到第一个出错的项：

- 名称 `id="key-name"`：必填，最长 100 字节（后端字段上限，中文 33 个字）；错误「请输入名称」/「名称太长了」。
- 分组 `<Select name="key-group">`：只列账号能用的分组（组织成员只有组织授权的）。菜单里每项是 `<KeyGroupOptionContent>`（`keys-group-option.tsx`，照原版 sub2api 选分组，2026-10-08）：左边分组名 `font-medium` + 分组描述 `mt-1 text-xs leading-5 text-muted-foreground whitespace-pre-line line-clamp-3`（没写不显示，整项 `title` 是全文）；右边竖排 `<RateBadge rate base>`（有专属倍率时先写 `<del>` 划掉的原倍率）与高峰标签 `Badge tone="warning"`「高峰 20:00–23:00 ×1.5」（`sm` 以下放到描述下面）；选好后框里显示 `<GroupWithRate>`（`SelectOption.display`）；菜单与输入框同宽、最高 `min(24rem, 60dvh)`；没选时第一项是「请选择分组」，只有一个分组时直接选上；错误「请选择分组」；分组读不到时红字「分组暂时加载不出来，请稍后再试」。
- 自定义密钥：标签行右边 `<Switch id="key-custom-switch">`；打开后输入框 `id="key-custom"`（`font-mono`），16–128 位，只能用字母、数字、下划线、连字符；提示同规则，错误「请输入自定义密钥」/「至少 16 位」/「最多 128 位」/「只能用字母、数字、下划线和连字符」。
- IP 限制：`<Switch id="key-ip-switch">`；打开后白名单 `id="key-ip-allow"`、黑名单 `id="key-ip-block"` 两个多行框（`sm:grid-cols-2`，`font-mono text-xs`），一行一个 IP 或网段，最多 100 条；提示「一行一个 IP 或网段，如 203.0.113.5、10.0.0.0/8」；错误「有一行不是 IP 或网段，或者超过 100 条」。
- 额度（US$）`id="key-quota"`：前缀 `$`，0–1000000，提示「不填或填 0 表示不限」。
- 限速：`<Switch id="key-rate-switch">`；打开后三个金额框并排：5 小时 `id="key-rate-5h"`、1 天 `key-rate-1d`、7 天 `key-rate-7d`；提示「这段时间内最多花多少美元，0 表示不限」。
- 有效期：`<Switch id="key-expiry-switch">`；打开后 `<SegmentedControl name="key-expiry-preset">` 7 天 / 30 天 / 90 天 / 自选，下面到期日 `<Input type="date" id="key-expiry-date">`（默认 30 天后；新建要晚于今天，最长 10 年）；提示「到期日当天结束后失效」。提交时换成「多少天后到期」。

底部：取消 + 创建（`data-create-submit`，提交中是加载态）。后端失败时表单最后一行红字（`role="alert"`，`data-key-error`）：自定义密钥已被占用、IP 名单里有认不出的地址、账号不能用这个分组、操作太频繁、没有成功。成功后弹窗内容换成「密钥已创建」+ 完整密钥代码框（`data-new-key-secret`）+ `CopyButton name="new-key"` +「完成」（`data-create-done`）；关掉弹窗时列表重新读取。

### K4 编辑弹窗 `<Dialog id="edit-key" title="编辑密钥">`

同创建的各项，去掉自定义密钥；分组可以换（和 sub2api 一样），现在的分组不在可选列表里时也照样列出来。设了额度时额度框下面一条「已用 {已用} / {上限}」+「重置已用额度」；设了限速时每个金额框下面「已用 {金额}」，右下「重置限速用量」。重置要先确认（`<ConfirmDialog id="reset-key-usage" tone="default">`，标题「把已用额度清零？」/「把限速用量清零？」，确认「清零」），确认后马上生效、不用点保存。有效期：不早于今天；只在改过时才提交（到期时刻写成那天 23:59:59 北京时间），关掉开关就是改成永久。保存成功后关弹窗、列表重新读取；失败时表单最后一行红字。

### K5 删除确认

`<ConfirmDialog id="delete-key" title="删除密钥「{名称}」？" description="删除后使用这个密钥的请求会立即失败，且无法恢复。" confirmLabel="删除" />`，确认后调后端删除并重读列表，删掉的是这一页最后一条时退回上一页；失败时表格上方红字。暂停 / 启用不需要确认。

**文案**（`consoleKeys`，英文见 `en/consoleKeys.json`）：`actions.*`、`filters.*`、`table.*`（含 `noGroup` 未分组）、`status.*`（启用 / 已暂停 / 额度用完 / 已过期）、`form.*`（各项名称与提示、`groupPlaceholder` 请选择分组、`quotaUsed` 已用 {used} / {limit}、`resetQuota`、`rateUsed` 已用 {used}、`resetRateUsage`、`expiryDays` {days} 天、`expiryCustom` 自选、`expiryDate` 到期日）、`create.*`、`edit.title`、`delete.*`、`reset.*`、`errors.*`（表单各项，与 `errors.action.*` 后端失败原因）、`loadError.*`、`empty.*`。

## O 组织 `src/blocks/console/organization/organization-page.tsx`（导出 `OrganizationPage`，拆成 `organization-*.tsx`）

2026-10-04 起接后端，只给组织管理员（组织创建者）。数据与改动见模块文档 `docs/模块设计/客户控制台-密钥与组织.md`，这里写版式。

**进页**：读当前用户（`useSession`）；不是组织管理员（个人用户、普通成员）时 `router.replace('/console/usage')`；读当前用户期间显示占位块（`data-org-loading`），读不到时 `EmptyState id="organization-error"` + 重试（整页重载）。侧栏的「组织」也只给组织管理员（`visibleNav(affiliateEnabled, orgOwner)`）。

**外层**：`<ConsolePage id="organization" title={组织名} actions={<RefreshButton />}>`（刷新重读整页）。组织被平台停用时最上面一条黄色提示（`data-org-suspended`）。下面是 `grid items-start gap-6 xl:grid-cols-2`：左 O1、右 O2；再下面 O3。

### O1 配额申请 `<Panel id="org-requests" title="配额申请">`

- 标题行右侧：状态 `Select name="org-request-status"`（待处理（默认）/ 全部 / 已发放 / 已驳回 / 已撤回；没开申请时不显示）+「申请设置」（`data-org-policy-open`）。
- 没开申请：`data-org-requests-off`「组织没有开配额申请」；没有记录：`EmptyState id="org-requests"`「暂无申请」。
- 每条 `data-org-request={id}`：申请人（组织内名称，没有就用邮箱）+ 金额；理由（最多两行）；时间、状态徽标（`data-org-request-status`：待处理 `warning`、已发放 `success`、已驳回与已撤回 `neutral`）、审批备注；待处理的右侧通过（`data-org-approve`，`ConfirmDialog id="org-approve" tone="default"`：「通过这条申请？」「{名字} 的额度会增加 {金额}。」）与驳回（`data-org-reject`，弹窗 `org-reject`：备注可选，最多 500 字，带字数）。
- 超过一页时下面分页（默认每页 10 条）。
- 申请设置弹窗 `org-policy`：申请方式 `Select name="org-policy-mode"`（关闭 / 先审批再加 / 申请了就加）；不关闭时单次最低 `#org-policy-min`、最高 `#org-policy-max`（最低大于 0、最高不低于最低）。

### O2 组织邀请码 `<Panel id="org-invitations" title="组织邀请码">`

- 标题行右侧：有效期 `Select name="org-invite-validity"`（1 天 / 7 天（默认）/ 30 天内有效 / 长期有效）+「创建邀请码」（primary，Plus 图标，`data-org-invite`）。
- 列表在区块里滚动（`max-h-96`），每条 `data-org-invitation={code}`：邀请码（等宽粗体，可换行）；「创建于 …」与「有效期至 …」或「长期有效」；状态徽标 `data-org-invitation-status`（有效 `success`；已使用、已停用、已过期 `neutral`；过了有效期但后端还记有效的算已过期）；有效、已使用的有复制邀请码 `data-copy="org-code"` 与复制邀请链接 `data-copy="org-link"`（`{本站}/register?invitation_code={code}`）；有效的有停用（`data-org-invitation-disable`，`ConfirmDialog id="org-disable-invitation"`：「停用这个邀请码？」「停用后不能再用它注册加入组织。」）。
- 空：`EmptyState id="org-invitations"`「还没有邀请码」。

### O3 成员 `section[data-org-members]`

- 标题行：「成员」+ 搜索 `#org-member-search`（`data-org-member-search`，搜索邮箱或用户名，停 300 毫秒才查）、状态 `Select name="org-member-status"`（全部状态 / 启用 / 已停用）、「周期发放（N）」`data-org-grant` 与「平分上限（N）」`data-org-split`（勾选后才能点，N 是勾选人数）。
- 新成员默认配额一行（卡片）：`data-org-default-quota`「新成员默认配额：每期 {金额} · {天} 天」或「新成员默认配额：未开启」+「开启」/「修改」（`data-org-default-open`）。还没读到时不显示这一行。
- `TableShell id="org-members"` → `Table minWidth={960}`，每行 `data-org-member={userId}`：

| 列 | 内容 |
|---|---|
| 勾选 | 表头勾这一页（`data-org-select-page`），每行 `data-org-select={userId}`；组织管理员本人没有勾选框；勾选跨页保留 |
| 名称 | 组织内名称，没有写「—」 |
| 邮箱 | 邮箱 + 用户名（小字） |
| 状态 | 组织管理员 `info`；启用 `success` / 已停用 `warning`（`data-org-member-status`） |
| 额度 | 固定上限金额；周期配额写金额 +「每 N 天」，指定时间生效的加「· 待生效」；不限额写「不限额」；管理员本人「—」 |
| 已消费 | 金额 |
| 剩余额度 | 金额（用完变黄）或「不限额」；周期配额生效中写「{时间} 重置」；有冻结金额写「冻结 {金额}」 |
| 操作（`sticky="right"`） | 改名（Pencil，`data-org-rename`）、设置配额（Wallet，`data-org-quota`）、停用 / 启用（Ban / CircleCheck，`data-org-toggle`；停用要 `ConfirmDialog id="org-disable-member"`：「停用成员「{名字}」？」「停用后这个人的调用会立即被拒绝，可以随时再启用。」）；管理员本人只有改名 |

- 分页在表格底部（后端分页）；读不到显示重试；搜索或筛选没结果「没有符合条件的成员」，没有成员「还没有成员」；行上操作失败时表格上方一句红字。

**弹窗**

- 改名 `org-rename`：名称 `#org-member-name`（1–50 个字）。
- 设置配额 `org-quota`：额度方式 `SegmentedControl name="org-quota-mode"`（不限额 / 固定累计上限 / 周期配额）；固定上限填 `#org-quota-amount`（提示「填 0 表示不让这个成员消费」）；周期配额填每期金额、周期天数（1–3650），「立即生效」开关关掉后选生效时间（北京时间）；成员原来有周期配额、改成另外两种时提示「保存后会清掉这个成员现有的周期配额」。
- 周期发放 `org-grant`：每期金额、周期天数、立即生效或生效时间，发给勾选的人。
- 平分上限 `org-split`：分配总额 `#org-split-total`，下面列出每人分到多少（`data-org-split-preview`）。
- 新成员默认配额 `org-default-quota`：每期金额、周期天数；两个勾选「同时发给现有没配周期配额的成员」（默认勾）与「同时覆盖现有已配周期配额的成员（立即换新一期）」（默认不勾）；已开启时左下角「关闭默认配额」（`data-org-default-off`，确认 `org-default-off-confirm`）。
- 弹窗里后端失败的原因写在最后一行（`data-org-error`）。

## 本页交互检查会找的东西

| 页面 | 操作 | 断言 |
|---|---|---|
| 密钥（需后端，本机测试账号） | 打开 `/console/keys` | 表头依次是名称、密钥、分组、状态、用量、额度、有效期、操作；「开发调试」一行的用量含「近 30 天 84 次」，分组格是「标准通道 ×0.15」 |
