## B 账单 `src/blocks/console/billing/billing-page.tsx`（导出 `BillingPage`，可拆 `billing-*.tsx`）

2026-10-04 起接后端（技术设计 18.5），照 onehop 账单页改版，去掉余额提醒。充值还没接真实支付，弹窗只是界面。

**外层**：`<ConsolePage id="billing" title={t('meta.title')}>`，从上到下：余额卡、兑换码（一整行）、交易记录，外加充值弹窗。

**取数**：`useBalanceSummary(reloadKey)`（`GET /api/portal/console/billing/summary`）；交易记录在 B3 里自己取。兑换成功后 `reloadKey + 1`，两份一起重新取。「今天」用 `useLiveClock()`（北京时间，挂载后才有），`since = usageSince(user.createdAt, today)`。登录失效时整页跳登录页并带回跳地址。

### B1 余额 `<Panel id="balance">`

1. 余额偏低（`isLowBalance`：余额低于 US$1，或按最近 30 天日均消耗撑不过 3 天）时最上面一条提示 `role="status"`、`data-low-balance`：`rounded-xl border border-warning/30 bg-warning-soft px-4 py-3 text-sm text-warning`，`TriangleAlert` 图标 +「余额偏低，可能影响调用，请尽快充值。」
2. 一行 `flex flex-col gap-4 sm:flex-row sm:items-start sm:justify-between`：左边「可用余额」小标签、余额 `text-4xl font-semibold tracking-tight tabular-nums`（`data-balance`；偏低时 `text-warning`）；最近有消耗时下面一行 `data-runway`「按当前速度约可用 {days} 天 · 日均 {avg}」（`balanceOutlook`：日均 = 最近 30 天消耗 ÷ 30，天数向下取整；没有消耗时不显示）。右边充值按钮：2026-10-09 起是打开卡网店铺的链接 `<a data-recharge="shop" target="_blank" rel="noopener noreferrer" className={buttonClass({ size: 'lg' })}>`（`Plus` +「充值」+ `ArrowUpRight`；地址是后台「充值链接」，`useRechargeUrl()` 读，没填时不显示）；在线支付的弹窗按钮 `<Button size="lg" data-recharge>` 按控制台功能开关 `recharge` 不显示。还没取到时余额位置是 `Skeleton`；取不到且手里没有旧数据时显示原因（查询太频繁 / 数据暂时取不到）与「重试」（`data-balance-retry`）。
3. `mt-6 grid gap-4 border-t border-border pt-5 sm:grid-cols-3 sm:gap-0 sm:divide-x`，三格（小标签 + `text-lg font-medium tabular-nums`，`data-stat=recharged|bonus|consumed`，数字 `data-stat-value`，格子 `sm:px-6 sm:first:pl-0`）：累计充值 `formatUsd(rechargedUsd)`；累计赠送大于 0 时 `+` 加绿色；累计消耗大于 0 时加 `-`。都是开户以来的累计。

### B2 兑换码 `<Panel id="redeem">`（一整行）

标题 `TicketCheck` 图标 +「兑换码」；标题行右边（`Panel` 的 `actions`）「购买兑换码」+ `ArrowUpRight` 小链接（`data-redeem-buy`，`text-sm font-medium`，新窗口打开同一个卡网店铺，没填充值链接时不显示）。`flex gap-2`：`<Input id="redeem-code" data-redeem-input placeholder="输入兑换码" className="font-mono" autoCapitalize="off" />` + 「兑换」`<Button data-redeem-submit className={CONTROL_BUTTON}>`。码区分大小写，只去首尾空白后 `POST /api/portal/console/billing/redeem { code }`。空码「请输入兑换码」；后端错误按原因提示：兑换码不存在 / 这个兑换码已经用过了 / 兑换码已过期 / 这个兑换码正在处理，请稍后再试 / 尝试次数过多，请稍后再试 / 服务暂时不可用，请稍后再试（`role="alert"`，焦点回输入框）。成功：清空输入框，`data-redeem-result` 绿字（余额码「已到账 {amount}」，并发数、订阅码「兑换成功」，4 秒后收起），通知页面重新取余额卡与交易记录。

### B3 交易记录 `<Panel id="transactions" title="交易记录" bodyClassName="p-0">`

只列余额变动：充值、兑换码、优惠码、邀请返利、管理员调整、退款（不含调用扣费）。`GET /api/portal/console/billing/ledger?page&size&type&source&q&min&max&from&to`（`useBalanceLedger(query, reloadKey)`，query 用 `useMemo` 算好），筛选与分页都在后端。

1. 标题行右侧：按月翻 `‹ {formatMonthTitle} ›`（`data-month-prev` / `data-month` / `data-month-next`；显示范围起点所在的月，翻到的月用 `monthRangeOf`，本月只到今天；开户那个月不能再往前、本月不能再往后）+ `<DateRangePicker align="end" today since>`（默认最近 30 天，预设范围跟着今天走）。
2. 筛选行 `grid gap-3 sm:grid-cols-2 lg:grid-cols-[1fr_1fr_2fr_1.4fr]`：交易类型 `<Select name="txn-type">`（全部 / 充值 / 兑换码 / 优惠码 / 邀请返利 / 管理员调整 / 退款）；来源 `<Select name="txn-source">`（全部 + 这个账号流水里出现过的来源，支付方式按中文名，认不出的原样显示）；订单号或兑换码 `<SearchInput id="txn-search">`；金额范围（US$）两个 `AmountInput`（`txn-min`、`txn-max`，负数与非数字不筛，填反了自动对调）。搜索框与金额框停下 0.4 秒才去查。改任何条件回第 1 页。
3. 表格 `<Table minWidth={760}>`，每行 `data-txn-row={id}`：日期（`formatDateTimeShort`）；金额（`formatSignedUsd`，入账 `text-success`，右对齐）；类型 Badge（充值 `info`；兑换码、优惠码、邀请返利 `success`；管理员调整 `neutral`；退款 `warning`），充值与退款旁边写付款方式；说明（充值「订单 {订单号}」、兑换码「兑换码 {码}」、优惠码「优惠码 {码}」、邀请返利「邀请返利转入余额」、管理员调整写备注、没备注写「管理员调整余额」、退款「订单 {订单号} 退款 · {原因}」，`truncate max-w-80`，完整文字在 `title`）；余额（这一笔之后的余额，右对齐）。下面 `Pagination`（总数、页数来自后端）。
4. 状态：还没取到时三条 `Skeleton`；重新取时旧数据变浅（`opacity-60`）；取不到时空状态（查询太频繁 / 数据暂时取不到 + 重试）；没有记录「还没有交易记录」；筛选无结果「没有符合条件的记录」+ 清除筛选。

### B4 充值弹窗 `<Dialog id="recharge" title="充值" footer={取消 + 去支付}>`

界面同前：四个档位（`data-recharge-amount`）或自定义金额（5–10000，取到分）、赠送提示、三种支付方式。首发不显示（同上）。还没接真实支付：「去支付」（`data-recharge-submit`）转 1.2 秒后关掉弹窗，余额不变；以后照 sub2api 原来的下单流程接。

## I 邀请返利 `src/blocks/console/invite/invite-page.tsx`（导出 `InvitePage`，可拆 `invite-*.tsx`）

2026-10-04 起接 sub2api 的邀请返利，返利由后端自动进余额（技术设计 18.7）。

**外层**：`<ConsolePage id="invite" title={t('meta.title')}>`。

**取数**：`useAffiliate(reloadKey)`（`GET /api/portal/console/invite`）：后台没开邀请返利时回 `{ enabled: false }`，页面 `<EmptyState id="invite-disabled" icon={Gift}>`「邀请返利没有开启」；开了回详情。还没取到时一块占位面板；取不到且没有旧数据时空状态（查询太频繁 / 数据暂时取不到 + 重试 `data-invite-retry`）。侧栏的「邀请」只在开关打开时显示（`visibleNav`，外壳里 `useAffiliateEnabled()` 读一次）。

### I1 邀请链接 `<Panel id="invite-link">`

1. 「你的邀请链接」+ 只读输入框 `data-invite-link`（`inviteLink(本站地址, 语言, 邀请码)`：`/register?aff=邀请码`，英文界面 `/en/register?aff=`）+ 复制按钮 + 分享下拉（复制链接、复制邀请码、生成分享文案「我在用 {site} 调用 Claude、GPT、Gemini 等模型，用我的链接注册：{link}」）。
2. 规则（`<b>` 小标题加粗）：邀请——发给朋友，对方用它注册后就和你绑定；返利——朋友每次充值到账，你获得到账金额 {rate} 的返利（`rules.ratePercent`）；后台设了有效期时「只算朋友注册后 {days} 天内的充值」，设了单人上限时「每位朋友最多为你带来 {amount} 返利」；到账——没有冻结期写「返利立刻进你的余额」，有冻结期写「返利冻结 {N 天 / N 小时}，到期后自动进你的余额」（`freezePeriod`，整天数写天）。
3. 三格 `StatCard size="sm"`（`sm:grid-cols-3`）：`rebate-total` 累计返利（历史返利）；`rebate-pending` 待到账（可转入 + 冻结中，可转入的会被后端自动转走）；`invited` 邀请人数，有人时 sub「其中 {n} 人已产生返利」（从被邀请人列表数）。

### I2 邀请记录 `<Panel id="invitees" title="邀请记录" bodyClassName="p-0">`

表格 `<Table minWidth={520}>`，每行 `data-invitee-row={用户 ID}`：用户（后端打过码的邮箱，没有邮箱时用户名，`font-mono text-xs`）；注册时间（`formatDateTimeShort`，没有时「—」）；带来的返利（`formatUsd`，大于 0 时 `text-success`，右对齐）。后端只给最近 100 人，邀请人数更多时标题行右侧「只显示最近 {n} 位」。没有记录时 `<EmptyState id="invitees" icon={Gift} title="还没有邀请" bordered={false} />`。

**文案**（`consoleInvite`）：按上面中文逐条建键，英文对译（「邀请：」→ "Invite:"，「返利：」→ "Rebate:"，「到账：」→ "Payout:"）。

## 本页交互检查会找的东西

| 页面 | 操作 | 断言 |
|---|---|---|
| 账单 | 用测试账号登录后打开 `/console/billing` | `[data-balance]` 以 `US$` 开头；三格 `[data-stat=recharged|bonus|consumed] [data-stat-value]` 都有数字；没有 `[data-panel="alert"]`；兑换码面板与余额卡同宽、标题带图标 |
| 账单 | 直接点 `[data-redeem-submit]` | `#redeem-code-error`「请输入兑换码」 |
| 账单 | 兑换码填一个不存在的码后点兑换 | `#redeem-code-error`「兑换码不存在」 |
| 账单 | 类型选「兑换码」（`[data-select="txn-type"]` → `[data-option="redeem"]`） | 测试账号没有兑换记录时出现「没有符合条件的记录」与清除筛选 |
| 账单 | 搜索框填 `sub2`，等 2 秒 | 1 行（测试账号那笔支付宝充值） |
| 账单 | 开户那个月 | `[data-month-prev]` 不能点；点 `[data-month-next]` 翻到本月后它也不能点 |
| 账单 | 打开 `/console/billing` | 后台填了充值链接时 `[data-recharge="shop"]` 与 `[data-redeem-buy]` 都指向店铺、新窗口打开，没填时都没有；兑换码一整行在 |
| 账单 | 兑换一张测试库里没用过的余额码 | `[data-redeem-result]`「已到账 …」，余额与累计赠送跟着变，交易记录多一行兑换码 |
| 邀请 | 后台开了邀请返利、用测试账号登录后打开 `/console/invite` | 侧栏有 `[data-nav="invite"]`；`[data-invite-link]` 以 `/register?aff={邀请码}` 结尾；规则第二条含真实比例 |
| 邀请 | 被邀请人兑换一张余额码（或在线充值） | 不用打开邀请页，邀请人余额立刻多了返利；邀请页累计返利增加、`[data-stat="rebate-pending"]` 不变；账单页交易记录多一笔「邀请返利」 |
| 邀请 | 后台设了冻结期时产生返利 | 待到账先有这笔，冻结期到了一分钟内自动进余额，规则写「返利冻结 N 天（小时）」 |
| 邀请 | 后台关掉邀请返利（等 30 秒缓存过期） | 侧栏没有「邀请」；直接打开页面是 `[data-empty="invite-disabled"]` |
