# 登录 `/login`、注册 `/register`、找回密码 `/forgot-password`、重置密码 `/reset-password`、服务条款 `/terms`、隐私政策 `/privacy`、文档 `/docs`、404 —— 逐区块规格（DESIGN.md 第 5 章之一）

> 先读完 `DESIGN.md` 全文再读本文件。令牌、共享组件签名、文案原则、写入边界都在 DESIGN.md，这里不重复。
> 规格里写了的元素一个都不能少；没写的细节按同一套令牌补齐，不要自己加区块、加文案。
> 凡是写了 `data-*` 属性、`id`、`aria-label` 的地方，交互检查会用到，**名字和取值不能改**。
> 登录注册文案放进 `src/messages/{zh,en}/auth.json`，文档与 404 放进 `src/messages/{zh,en}/misc.json`（已有的 `meta` 键原样保留）。中文照本文件，英文给了的照抄、没给的按专业克制的语气对译。

照 Aceternity 模板的 `/login`、`/signup`：没有顶栏页脚，左半屏表单、右半屏浅灰展示区。和模板不同的三处：注册表单顶部多一个「个人注册 / 创建组织」分段切换（登录不区分账号类型，个人与组织成员都用邮箱和密码登录）；GitHub 按钮换成谷歌按钮（后台开了谷歌登录才显示，2026-10-07 接通，见 A1 第 4 项、A2 第 6 项与 A6）；右半屏的头像换成模型厂商标志。

登录已接后端（2026-10-03）：提交经官网服务器的 `/api/portal/auth/login` 转给后端，成功后进回跳地址或控制台 `/console/usage`，失败在按钮上方显示原因；账号开了两步验证时切到第二步（见 A1 第二步）。注册已接后端（2026-10-03）：规则与现有 sub2api 注册页一致（见 A2），注册成功即为登录状态，进控制台 `/console/usage`。找回密码已接后端（2026-10-05）：照 sub2api 原来的找回密码、重置密码两页（见 A4、A5）。不弹提示、不写任何「暂未开放」之类的文字，还没接的功能直接不显示入口。

页面布局由页面文件负责（地基已写）：`<div className="grid min-h-dvh lg:grid-cols-2">{左表单区块}<AuthShowcase /></div>`。

本页节奏：左白底表单，右浅灰 surface 底加虚线框。
本页核心动作：填表、提交（注册时先选个人注册或创建组织）。
最重要的区块：**A1 登录表单**。

注册类型存网址：`useUrlState('account', ['personal', 'organization'] as const, 'personal')`，只有注册页用；登录页与注册页互相跳转不带参数。

注册页显示哪些输入项由后端公开开关决定：打开时 `useAuthSettings()`（`src/lib/auth/use-auth-settings.ts`）经 `/api/portal/auth/settings` 读一次，读到之前按兜底值（开放注册、开着优惠码，其余关）画、提交按钮禁用。邀请码框始终显示：开了「邀请码注册」时必填，没开时标「选填」。

## A1 登录表单 `src/blocks/auth/login-panel.tsx`（`'use client'`）

**外层**：`<AuthPanelFrame id="login">`（`src/blocks/auth/auth-panel-frame.tsx`，登录、注册、找回、重置四页共用）：`<section id className="flex min-h-dvh flex-col px-6 py-8 sm:px-12 lg:px-16 xl:px-24">`，内层 `<div className="mx-auto flex w-full max-w-md flex-1 flex-col">`。

**元素**：

1. 顶部一行（外框里）`flex items-center justify-between`：`<Brand />` + `<div className="flex items-center gap-1"><LanguageSwitcher /><ThemeToggle /></div>`。
2. 表单主体（外框里）`<div className="flex flex-1 flex-col justify-center py-12">`：
   1. 标题 `<h1 className="text-2xl font-semibold tracking-tight text-foreground">{t('login.title')}</h1>`
   2. 表单 `<form noValidate onSubmit className="mt-8 space-y-5" data-login-form>`（不区分账号类型）：
      - 邮箱：`<Field label={t('fields.email')} htmlFor="email" error={errors.email}><Input id="email" type="email" data-login-email autoComplete="email" placeholder="name@company.com" … /></Field>`
      - 密码：`<Field label={t('fields.password')} htmlFor="password" error={errors.password}>`（后台开了找回密码时，标签行右侧是 `<Link href="/forgot-password" data-to-forgot className="text-sm text-muted-foreground hover:text-foreground">{t('login.forgot')}</Link>`，开关由 `useAuthSettings()` 读），输入框外包 `relative`：`<Input id="password" type={show ? 'text' : 'password'} data-login-password autoComplete="current-password" className="pr-10" … />` + 右侧按钮 `<button type="button" data-password-toggle aria-label={show ? t('fields.hidePassword') : t('fields.showPassword')} className="absolute inset-y-0 right-0 flex w-10 items-center justify-center text-subtle-foreground hover:text-foreground">`（图标 `Eye` / `EyeOff` `size-4`）。
      - 整表错误提示 `<AuthFormAlert message={formError} />`（`src/blocks/auth/auth-form-alert.tsx`）：`<p role="alert" data-auth-alert className="rounded-md bg-danger-soft px-3 py-2 text-sm text-danger">`，没有消息时不渲染
      - 提交 `<Button type="submit" block loading={submitting} data-login-submit>{t('login.submit')}</Button>`
   3. 注册链接 `mt-4 text-center text-sm text-muted-foreground`：「{t('login.noAccount')}」+ `<Link href="/register" data-to-register className="font-medium text-foreground hover:underline">{t('login.toRegister')}</Link>`
   4. 分隔线与谷歌按钮（2026-10-07 起，后台开了谷歌登录 `settings.googleOAuthEnabled` 时才有）：`<AuthGoogleButton label={t('login.google')} dataAttribute="data-google-login" startUrl={…} />`（`src/blocks/auth/auth-google-button.tsx`，登录注册共用）。分隔线 `mt-6 flex items-center gap-3 text-xs text-subtle-foreground`，两边 `h-px flex-1 bg-border`、中间 `t('divider')`；下面 `mt-6` 整宽次要按钮，谷歌标志 `/brands/google.svg`（`size-4`）+ 文字。点了按钮转圈、整页跳到 `googleStartUrl({ locale, next })`（`src/lib/auth/google-oauth.ts`，next 取网址里的回跳地址）；从谷歌按浏览器返回回来时按钮恢复可点。
   5. 条款：`<AuthLegalNote action="login" />`（`src/blocks/auth/auth-legal-note.tsx`，注册与完成注册页用 `action="register"`）。`<p className="mt-8 text-center text-xs leading-5 text-subtle-foreground">` 里 `t.rich('login.terms', …)`，`<terms>` 渲染成 `<Link href="/terms" target="_blank" className="underline underline-offset-4 hover:text-foreground">`，`<privacy>` 同样链到 `/privacy`；新标签页打开，填了一半的表单不丢。

**交互**（状态：`values: { email: string; password: string }`、`errors: Partial<Record<'email' | 'password', string>>`、`show: boolean`、`submitting: boolean`）：
- 所有输入框受控。
- 提交时校验，规则按顺序：
  - 邮箱为空 → `fields.errors.emailRequired`；不符合 `/^[^\s@]+@[^\s@]+\.[^\s@]+$/` → `fields.errors.emailInvalid`
  - 密码为空 → `fields.errors.passwordRequired`（登录不查长度，老账号可能是 6 位密码）
  每个字段只报它的第一条错误，所有出错字段同时标红；焦点放到第一个出错的输入框，对应输入框 `aria-invalid="true"`、`aria-describedby` 指向错误文字。
- 没有错误时 `submitting` 置真，调 `signIn(email, password)`（`src/lib/session/client.ts`）：
  - 成功：`router.replace(safeNextPath(网址里的 next))`，只回控制台里的站内地址，否则去 `/console/usage`；
  - 要两步验证：切到第二步；
  - 失败：`formError` 按原因取 `login.errors.<原因>`（INVALID_CREDENTIALS、USER_NOT_ACTIVE、ORGANIZATION_DISABLED、TOO_MANY_REQUESTS、BACKEND_UNAVAILABLE），其余用 `login.errors.generic`；密码错误时清空密码框并聚焦。
- 输入时清掉该字段的错误和整表提示。
- 谷歌登录失败时官网服务器跳回 `/login?oauth_error=<原因>`：整表提示显示 `login.oauthErrors.<原因>`（读网址参数 `useUrlText('oauth_error')`，服务端渲染时没有、挂载后才出现）；一输入或提交就从网址里去掉、提示跟着消失。

**第二步：两步验证** `src/blocks/auth/login-two-factor.tsx`（替换掉表单主体，顶部一行不变）：
- `<div data-login-two-factor>`：标题 `t('login.twoFactor.title')`（两步验证）；一句 `mt-2 text-sm text-muted-foreground`「{t('login.twoFactor.desc', { email: 打码邮箱 })}」。
- 表单 `mt-8 space-y-5`：`<Field label={t('login.twoFactor.code')} htmlFor="totp-code">` + `<Input id="totp-code" data-login-totp inputMode="numeric" autoComplete="one-time-code" maxLength={6} placeholder="000000" className="font-mono tracking-[0.3em]">`（只留数字、最多 6 位，打开时自动聚焦）；`<AuthFormAlert />`；`<Button type="submit" block data-login-totp-submit>{t('login.twoFactor.submit')}</Button>`。
- 下方 `<button type="button" data-login-totp-back className="mt-4 w-full text-center text-sm text-muted-foreground hover:text-foreground">{t('login.twoFactor.back')}</button>` 回第一步。
- 不足 6 位数字 → 字段错误 `login.twoFactor.errors.format`；验证码错误 → 整表提示 `errors.invalid` 并清空重输；尝试过多 → `errors.tooMany`；临时凭证过期 → 回第一步并在第一步显示 `errors.expired`。
**状态**：默认、输入中、出错（红框 + 红字）、后端返回错误（按钮上方红底提示）、提交中（按钮转圈、禁用）、两步验证。邮箱超长时输入框内部滚动，不撑宽。

**响应式**：`lg` 以下右侧展示区隐藏，表单占满屏宽，左右内边距 24px。

**文案**（`auth`，中文 / 英文）：

## A2 注册表单 `src/blocks/auth/register-panel.tsx`（`'use client'`）

规则照搬现有 sub2api 注册页（`frontend/src/views/auth/RegisterView.vue`、`EmailVerifyView.vue`），写成纯函数放在 `src/lib/auth/register-form.ts`。组件拆成：`register-panel.tsx`（编排：读开关、校验、提交、切步骤）、`register-fields.tsx`（第一步的输入项）、`register-code-field.tsx`（邀请码 / 返利码 / 优惠码共用的输入框加校验状态行）、`register-verify-step.tsx`（第二步验证邮箱）、`use-register-messages.ts`（错误与校验状态的文案）。

**外层、顶部一行、主体结构**同 A1，`<AuthPanelFrame id="register">`。

**元素**（和 A1 的差异）：
1. 标题 `t('register.title')`。
2. 后台关了注册（读到开关后 `registrationEnabled` 为假）：标题下只放 `<p data-register-closed className="mt-8 rounded-md bg-muted px-4 py-3 text-sm text-muted-foreground">{t('register.closed')}</p>` 和登录链接，下面 3、4、6 都不显示。
3. 注册类型切换 `<SegmentedControl name="account" className="mt-6 [&>button]:flex-1 [&>button]:justify-center" value={account} onChange={切换并清空错误} ariaLabel={t('account.label')} options={[{ value: 'personal', label: t('account.registerPersonal') }, { value: 'organization', label: t('account.registerOrganization') }]} />`（两项平分宽度）。邀请码识别为组织邀请码时整条隐藏，并切回 `personal`（组织邀请码只能加入，不能再创建组织）。
4. 表单 `data-register-form`，字段顺序：
   - 仅创建组织：组织名称 `data-register-org-name`（`fields.orgName`，placeholder `fields.orgNamePlaceholder`，`autoComplete="organization"`，最多 100 字）
   - 邮箱 `data-register-email`（个人 `fields.email`，创建组织 `fields.adminEmail`）
   - 密码 `data-register-password`（`autoComplete="new-password"`，带显示切换，`hint` 为 `fields.passwordHint`）
   - 邀请码 `data-register-invite`（`fields.invite`，始终显示；没开「邀请码注册」时标签后加 `ml-1.5 text-xs font-normal text-subtle-foreground` 的 `fields.optional`）
   - 仅创建组织或邀请码识别为组织邀请码时：你在组织中的名称 `data-register-member-name`（`fields.memberName`，placeholder `fields.memberNamePlaceholder`，`autoComplete="name"`，最多 50 字）
   - 仅后台开了邀请返利：返利码 `data-register-aff`（`fields.aff`，选填，不做实时校验）
   - 仅后台开了优惠码：优惠码 `data-register-promo`（`fields.promo`，选填）
   - 邀请码、优惠码输入框下方一行实时校验状态 `<p id="{id}-status" data-code-status="muted|success|danger" className="flex items-center gap-1.5 text-xs">`：校验中 `LoaderCircle` 转圈 + `fields.checking`（`text-subtle-foreground`）；有效 `Check` + 文字（`text-success`）；无效 `X` + 文字（`text-danger`）。字段本身有错误时只显示错误、不显示状态行。
   - 整表错误提示 `<AuthFormAlert message={formError} />`
   - 提交按钮 `data-register-submit`：开了邮箱验证时 `t('register.next')`（下一步）；否则个人 `t('register.submitPersonal')`（注册），创建组织 `t('register.submitOrganization')`（创建组织）。开关读到之前禁用。
5. 登录链接：「{t('register.hasAccount')}」+ `<Link href="/login" data-to-login>`{t('register.toLogin')}`</Link>`。
6. 后台开了谷歌登录且没关注册时，登录链接下面同 A1 的分隔线与谷歌按钮（`t('register.google')`，`data-google-register`）：点之前把注册类型、组织名称、组织内名称、邀请码、返利码存进本页会话（`storeGoogleDraft`，`sessionStorage`），完成注册页预填；发起时只带返利码和校验通过的优惠码（优惠码只能在发起时交给后台），组织与邀请码在完成注册时才提交——这里填过又改主意时，后台不会按旧值建组织。条款（`t.rich('register.terms', …)`）同 A1。

**交互**：
- 所有输入框受控；输入时清掉该字段的错误和整表提示。切换注册类型时清空错误（输入值保留），组织名称、组织内名称随之出现 / 消失。
- 邀请码、优惠码边输边校验：停手 500 毫秒后问后端（`useCodeCheck`，`src/lib/auth/use-code-check.ts`），只认最后一次输入的结果；清空即回到未校验。邀请码有效时：平台邀请码 `fields.inviteValid`，组织邀请码 `fields.inviteValidOrganization`；无效时过期 `fields.inviteExpired`，其余 `fields.inviteInvalid`。优惠码有效时 `fields.promoValid`（带赠送金额）；无效按后端错误码取 `promoNotFound / promoExpired / promoDisabled / promoMaxUsed / promoAlreadyUsed`，其余 `promoInvalid`。
- 网址带 `?invite=`（或 `?invitation_code=`）、`?promo=`（后台开了优惠码时）、`?aff=`（或 `?aff_code=`）时，读到开关后自动填好并立即校验；返利码存本机 30 天，注册成功后清掉（`src/lib/auth/affiliate.ts`）。
- 提交时按顺序：
  1. 字段校验（规则见 `validateRegister`）：创建组织时组织名称为空 → `fields.errors.orgNameRequired`；邮箱、密码为空或邮箱格式同 A1；密码不足 6 位 → `passwordShort`；后台设了邮箱后缀白名单且没开按域名限量注册时，域名不在单子里 → `emailSuffix`（列出最多 5 个可用域名，其余写「等 N 个」）；开了邀请码注册而邀请码为空 → `inviteRequired`；需要组织内名称而为空 → `memberNameRequired`。所有出错字段同时标红，焦点按 组织名称 → 邮箱 → 密码 → 邀请码 → 组织内名称 落到第一个出错项。
  2. 填了的邀请码、优惠码：校验中 → 整表提示 `register.blocks.inviteChecking / promoChecking`；无效 → `register.blocks.inviteInvalid / promoInvalid`。邀请码填了还没来得及校验，就当场校验一次，识别为组织邀请码后重新做第 1 步（要组织内名称）。
  3. 开了邮箱验证 → 切到第二步；没开 → 直接注册。
- 注册成功：清掉返利码，`router.replace('/console/usage')`。失败：整表提示按原因取 `register.errors.<原因>`，没有对应文案的用 `register.errors.generic`。

**第二步：验证邮箱** `src/blocks/auth/register-verify-step.tsx`（替换掉表单主体，顶部一行不变）：
