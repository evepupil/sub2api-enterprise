## T 工单 `src/blocks/console/tickets/tickets-page.tsx`（导出 `TicketsPage`，可拆 `tickets-*.tsx`）

**外层**：`<ConsolePage id="tickets" title={t('meta.title')} actions={新建工单（primary，Plus 图标，data-create-ticket）}>`。

**页内状态**：`tickets: Ticket[]`（初始 `TICKETS`）、`status: TicketStatus | 'all'`、`openId: string | null`（抽屉里看的工单）、新建弹窗状态与草稿。

### T1 筛选

`<Select name="ticket-status" className="w-48">`：全部状态 / 处理中 / 待你回复 / 已解决 / 已关闭。数据 `filterTickets(tickets, status)`。

### T2 工单表

`<TableShell id="tickets">` → `<Table minWidth={720}>`，每行 `data-ticket-row={id}`：编号（`font-mono text-xs`）；标题（按钮 `data-ticket-open={id}`，`font-medium hover:underline text-left`，`line-clamp-1`，点了打开抽屉）；分类；状态（处理中 `info`、待你回复 `warning`、已解决 `success`、已关闭 `neutral`，`data-ticket-status={status}`）；更新时间（`formatDateTimeShort`）。

**空状态**：
- 一个工单都没有（`tickets` 为空）：`<EmptyState id="tickets" icon={LifeBuoy} title="还没有工单" action={<Button>提交第一个工单</Button>} />`。
- 筛选没结果：标题「没有这个状态的工单」，操作「查看全部」（把状态切回全部）。

### T3 工单详情抽屉 `<Sheet id="ticket-detail" title={#{id} {标题}}>`

1. 顶部信息 `px-5 py-4 flex flex-wrap gap-2`：状态徽标、分类徽标（`outline`）、「创建于 {时间}」；有关联请求时一行「关联请求」+ `font-mono text-xs` 的请求 ID + `CopyButton name="ticket-request"`。
2. 对话 `space-y-4 px-5 pb-5`：客服消息左对齐（上方小字「客服 · {时间}」，气泡 `rounded-2xl rounded-tl-md bg-muted px-4 py-3 text-sm whitespace-pre-wrap`），用户消息右对齐（上方「你 · {时间}」，气泡 `bg-primary text-primary-foreground rounded-tr-md`），`data-ticket-message={from}`。
3. 底部（`Sheet` 的 `footer`）：
   - 未关闭的工单：多行输入 `id="ticket-reply"`（`rows={3}`，`resize-none`，占位「补充说明或回复客服」）+ 一行按钮：左「标记为已解决」（secondary，`data-ticket-resolve`，已解决的工单换成「重新打开」`data-ticket-reopen`）；右「发送」（`data-ticket-send`，空内容禁用）。发送：加一条用户消息（`ts` 用 `CONSOLE_NOW`），状态改为「处理中」，更新时间同步，清空输入。
   - 已关闭的工单：一行 `text-sm text-subtle-foreground`「工单已关闭」。

### T4 新建工单弹窗 `<Dialog id="new-ticket" title="新建工单" footer={取消 + 提交}>`

字段（`Field`）：

- 标题 `id="ticket-subject"`：必填，最多 `TICKET_LIMITS.subjectMax` 字。错误「请输入标题」/「标题最多 80 个字」。
- 分类：`<Select name="ticket-category">` 接口与调用 / 账单与发票 / 账号与组织 / 其他（`TICKET_CATEGORIES`），默认接口与调用。
- 关联请求 ID `id="ticket-request"`：选填，占位「req_…」，填了必须以 `req_` 开头（错误「请求 ID 以 req_ 开头」）。
- 问题描述 `id="ticket-body"`：多行（`rows={6}`），必填，`bodyMin`–`bodyMax` 字，右下角字数「{n} / 2000」；错误「请描述遇到的问题」/「至少写 10 个字」。

提交 `data-ticket-submit`：校验（所有出错字段同时标红、焦点落第一个），通过后加载 1 秒，新工单编号 = 现有最大编号 + 1（`T-1025`），状态「处理中」，第一条消息是描述，加到列表最前，关闭弹窗并打开它的详情抽屉。

**分类与状态名**：`api` 接口与调用 / API & requests；`billing` 账单与发票 / Billing & invoices；`account` 账号与组织 / Account & organization；`other` 其他 / Other；`open` 处理中 / In progress；`awaiting` 待你回复 / Awaiting your reply；`resolved` 已解决 / Resolved；`closed` 已关闭 / Closed。

**文案**（`consoleTickets`）：按上面中文逐条建键，英文对译。

## S 账户设置 `src/blocks/console/settings/settings-page.tsx`（导出 `SettingsPage`，可拆 `settings-*.tsx`）

**外层**：`<ConsolePage id="settings" title={t('meta.title')}>`，内容区 `max-w-3xl`（`className` 传给 `ConsolePage`），面板竖排。

### S1 个人资料 `<Panel id="profile" title="个人资料">`

- 左边大头像（`Avatar`，`size-14 text-base`，从 `@/components/console/shell/user-menu` 引入）；右边表单：
  - 名称 `id="profile-name"`（默认 `CURRENT_USER.name[locale]`，必填，最多 32 字，错误「请输入名称」/「名称最多 32 个字」）；
  - 邮箱：只读 `Input`（`CURRENT_USER.email`，`disabled` 样式）+ 旁边 `<Badge tone="success">已验证</Badge>`。
- 底部右侧「保存」`data-profile-save`：没有改动时禁用；加载 800ms；成功后旁边短暂显示「已保存」2 秒。

### S2 登录密码 `<Panel id="password" title="登录密码">`

三个 `AuthPasswordInput` 一样的密码框（可显示 / 隐藏，用 `Input` + 眼睛按钮自己拼，不 import 登录页的区块）：当前密码 `id="password-current"`、新密码 `id="password-new"`（至少 8 位，且不能与当前密码相同）、确认新密码 `id="password-confirm"`（与新密码一致）。错误：「请输入当前密码」「新密码至少 8 位」「新密码不能与当前密码相同」「两次输入的密码不一致」。「修改密码」`data-password-save`：校验通过后加载 1 秒，清空三个输入框，旁边短暂显示「密码已修改」。

### S3 两步验证 `<Panel id="two-factor" title="两步验证">`

一行：左边说明「登录时除了密码，还要输入验证器 App 里的 6 位动态码。」（功能说明，保留）+ 状态徽标（已开启 `success` / 未开启 `neutral`）；右边 `<Switch name="two-factor" />`（默认关闭）。

- 打开开关时不直接打开，而是弹出 `<Dialog id="two-factor-setup" title="开启两步验证">`：左边一个 `size-36` 的二维码占位图（用 `QrCode` 图标居中放在 `rounded-xl border bg-surface` 的方框里）；右边「也可以手动输入密钥」+ `font-mono` 的 16 位密钥（固定占位 `NXQK 2F7L 9WPA 4MTZ`）+ `CopyButton`；下面 6 位验证码输入 `id="two-factor-code"`（`inputMode="numeric"`，只能 6 位数字，错误「请输入 6 位数字验证码」）。「确认开启」`data-two-factor-confirm`：校验通过后加载 800ms，开关变为开启，关闭弹窗。
- 关闭开关时用 `ConfirmDialog id="two-factor-off"`「关闭两步验证？」，说明「关闭后登录只需要密码。」，确认后关闭。

### S4 第三方账号 `<Panel id="connections" title="第三方账号">`

一行：谷歌标志（`/brands/google.svg`，`size-5`）+「Google」+ 状态（未绑定 `text-subtle-foreground` / 已绑定的邮箱）；右边按钮：未绑定「绑定」（secondary，`data-connect-google`，加载 1 秒后变已绑定，邮箱显示 `CURRENT_USER.email`），已绑定「解绑」（ConfirmDialog `id="disconnect-google"`）。

**文案**（`consoleSettings`）：按上面中文逐条建键，英文对译。

## 本页交互检查会找的东西

| 页面 | 操作 | 断言 |
|---|---|---|
| 工单 | 打开 `/console/tickets` | `[data-ticket-row]` 有 3 行，第一行是 `T-1024` |
| 工单 | 状态选「已解决」 | 只剩 `[data-ticket-row="T-1019"]` |
| 工单 | 状态选「已关闭」 | 出现 `[data-empty="tickets"]` |
| 工单 | 点 `[data-create-ticket]` 后直接点 `[data-ticket-submit]` | 出现 2 个以上 `[role="alert"]`，第一个是「请输入标题」 |
| 工单 | 标题填「测试工单」、描述填「生图接口返回 500 错误，请帮忙看看」后提交，等 1.5 秒 | 出现 `[data-ticket-row="T-1025"]` 与 `[data-sheet="ticket-detail"]` |
| 设置 | 打开 `/console/settings` | 有 `[data-panel="profile"]`、`password`、`two-factor`、`connections` |
| 设置 | 点 `[data-switch="two-factor"]` | 出现 `[data-dialog="two-factor-setup"]` |
| 设置 | 新密码填 `123`、点 `[data-password-save]` | 出现 `[role="alert"]` |
