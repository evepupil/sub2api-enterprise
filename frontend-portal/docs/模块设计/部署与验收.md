# 部署与验收

模块定位：独立发布、路由分流与整站验收。

对应代码：`Dockerfile`、`deploy/`、`scripts/prepare-standalone.mjs`、`src/app/api/health/`、根仓库 `.github/workflows/portal-ci.yml`。

所属里程碑：[M5](../roadmap.md#m5) · 当前状态：进行中 · 最近更新：2026-09-27

依据：[架构设计](../架构设计.md) · [技术设计](../技术设计.md) · [前端设计](../前端设计.md)

本轮连续实施，接口、页面与验收细节见[团队与交付实施契约](../../design/team-and-delivery.md)。业务规则以当前底座为准。

## 1. 职责与边界

覆盖新站的构建、联调、发布与回退。客户网页走新前端，账号接口、支付通知和模型调用走 Go；原管理后台保留单独入口。

## 2. 结构与数据流

独立打包 Next.js 服务与静态资源，入口代理按路由表转发。Next.js 读取底座公开信息，并通过限定客户路径的同域代理承接登录后的查询和操作。模型调用直接交给 Go，不经过客户接口代理。

部署由前端容器和 Nginx 入口组成，连接已运行的 Go 服务；镜像不包含数据库。资源准备脚本将静态文件复制到独立产物实际读取的位置，缺少必要资源直接失败。运行地址在启动时注入。

## 3. 关键决策

模型目录使用 `/catalog`，已有 `/models` 留给模型接口。推理流式响应和长连接直达 Go，不能由 Next.js 页面兜底。Go 的内嵌页面回退规则也要核对，保证模型别名不会被返回成 HTML。

- 客户页面、`/_next/`、`/api/portal/` 和 `/api/health` 给 Next.js；`/api/v1/`、`/v1/`、Gemini、Codex 及其他模型入口给 Go。`/health` 保留为 Go 健康检查。
- 底座旧网页会拦截部分已注册的根路径模型别名。入口将这些别名转到等效 `/v1/` 路径，保留请求方法、查询、请求体和升级头，避免改动底座或原后台产物。
- 流式请求关闭请求和响应缓冲，长连接超时为 1800 秒。上传大小由各业务服务已有规则控制，入口不另加默认 1 MiB 限制。
- 代理清除客户端伪造的来源身份头，访问日志不保存查询串。容器更换后通过 Docker DNS 重新解析上游，避免沿用失效地址。
- Linux 镜像内单独安装依赖，非管理员用户运行。只给前端发版，不变更 Go 镜像或数据库结构。保留上一版镜像，通过替换明确版本标签回退。

本轮联调另修复了底座默认额度保存响应遗漏配置的问题，可通过原底座发布流程更新；客户前端的构建和版本回退继续独立进行，无需数据库迁移。

## 4. 当前实现

已提供多阶段独立镜像、Compose 环境模板、入口转发、健康检查和可选管理域名模板。Portal CI 对新前端运行完整工程检查、生产构建与镜像构建；不自动发布到未知环境。

完整构建、启动、地址填写、入口检查、升级和回退步骤见[部署操作说明](../../deploy/README.md)。实际官网域名、运行服务器和外层 HTTPS 入口尚未指定，因此没有修改任何线上入口。

## 5. 验证方式

工程检查包括格式、静态分析、严格类型、核心规则测试、生产构建、文档链接及模块双向引用。隔离本地 Go、PostgreSQL、Redis 和邮件环境承接账号、密钥、消费及组织真实接口联调；本地模拟支付只验证签名回调和到账流程。

发布形态使用带旧后台嵌入资源的 Go 二进制，核对官网与 API 分流、静态资源、错误返回、上传体、SSE 首段实时到达、WebSocket、容器更换与版本回退。流式及长连接使用本地模拟上游，不产生模型费用。

本地最终执行 29 项部署检查，全部通过；另完成实际 A → B → A 镜像回退。更换上游时容器地址实际变化，仍能经入口访问。最终服务使用正式产物镜像，测试版本标记返回 404，静态资源返回 200。主控另行核对健康检查、模型目录、模型鉴权、组织鉴权与管理接口拒绝；详细结果见[首版联调记录](../验收/2026-09-27-首版联调.md)。

前端专属 GitHub 检查已通过。原项目全仓检查仍报告后端既有测试编译问题，安全扫描还检出原有依赖告警；相关代码和依赖本轮未改，不能将新前端通过等同于整个底座通过。

浏览器工具当前没有可连接的浏览器，尚无本轮桌面、手机、键盘和弹窗实际点击验收结果。已询问是否明确改用 Playwright 驱动 Edge；答复前不切换自动化工具。不能用类型检查、HTTP 页面返回或服务端渲染代替浏览器验收。

## 6. 待扩展项

首版交付尚需在指定目标验证实际域名、TLS 与外层代理，补齐浏览器操作验收；已启用的外部登录、设备通行密钥与真实支付供应商需对应测试配置。容量测试按正式目标开展。上述内容未验证前，M5 不记为已完成。
