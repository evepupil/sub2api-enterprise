# 部署与验收

模块定位：独立发布、路由分流与整站验收。

对应代码：`frontend-portal/` 的独立构建和部署文件（规划）；既有 `deploy/` 与 Go 路由。

所属里程碑：[M5](../roadmap.md#m5) · 当前状态：未开始 · 最近更新：2026-09-27

依据：[架构设计](../架构设计.md) · [技术设计](../技术设计.md) · [前端设计](../前端设计.md)

本文件为规划归档，实施前按对应里程碑补齐详细契约与验收规格。

## 1. 职责与边界

覆盖新站的构建、联调、发布与回退。客户网页走新前端，账号接口、支付通知和模型调用走 Go；原管理后台保留单独入口。

## 2. 结构与数据流

独立打包 Next.js 服务与静态资源，入口代理按路由表转发。先在批准的验证环境检查业务与模型调用路径，再按已授权的发布范围切换网页入口，保留可回退产物。

## 3. 关键决策

模型目录使用 `/catalog`，已有 `/models` 留给模型接口。推理流式响应和长连接直达 Go，不能由 Next.js 页面兜底。Go 的内嵌页面回退规则也要核对，保证模型别名不会被返回成 HTML。

## 4. 当前实现

现有 Docker 构建将旧 frontend 打入 Go，部署模板依赖既有数据库与缓存。新前端部署配置未建立，实际域名、代理配置、支付回跳及运行容量未核实。

## 5. 验证方式

检查十四页关键流程、登录恢复、支付状态、三种身份、模型与状态空/错数据、桌面/手机、键盘和弹层；验证业务 API、模型调用、流式返回与 WebSocket 的路由。只有实际运行证据才能标为完成。

## 6. 待扩展项

实施前补齐域名、端口、回调、构建版本、发布/回退命令与验收结果；不在设计阶段创建服务、修改域名或启动开发服务器。
