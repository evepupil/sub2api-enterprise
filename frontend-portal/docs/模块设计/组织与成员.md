# 组织与成员

模块定位：组织资料、成员邀请、成员状态与消费配额。

对应代码：`frontend-portal/src/features/organization/`（规划）；复用既有组织服务。

所属里程碑：[M4](../roadmap.md#m4) · 当前状态：未开始 · 最近更新：2026-09-27

依据：[架构设计](../架构设计.md) · [技术设计](../技术设计.md) · [前端设计](../前端设计.md)

本文件为规划归档，实施前按对应里程碑补齐详细契约与验收规格。

## 1. 职责与边界

覆盖页面 14；创建/加入组织入口由 M2 注册流程承接。使用已有的单组织归属、管理员与成员规则，不增加多组织切换或更多角色。

## 2. 结构与数据流

根据当前身份取组织摘要，再由组织接口读取成员和额度。后端决定调用者管理权限和组织范围；前端展示结果并更新相关成员、配额与摘要查询。

## 3. 关键决策

组织管理员与平台管理员分别判断；配额表示消费上限，分配配额不会把钱转到成员余额。普通成员只有已有权限允许的操作；停用与额度变更以服务端结果为准。

## 4. 当前实现

现有底座具备组织注册、邀请、成员启停、配额和付款归属规则。新客户组织页面未实现；原业务历史验收不等于新界面已验收。

## 5. 验证方式

测试身份映射和配额状态，联调管理员与普通成员、跨组织访问拒绝、邀请失效、停用和并发修改后的显示。现有周期配额与申请机制的页面承接按底座启用情况核对。

## 6. 待扩展项

实施前固定成员表单、邀请和已有配额操作的界面契约；不扩展新的组织管理能力。
