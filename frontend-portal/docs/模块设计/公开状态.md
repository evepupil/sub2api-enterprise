# 公开状态

模块定位：官网可用率、当前响应速度和近期可用性记录。

对应代码：`frontend-portal/src/features/status/`（规划）；既有 `backend/internal/service/public_status.go` 与渠道监测服务。

所属里程碑：[M1](../roadmap.md#m1) · 当前状态：未开始 · 最近更新：2026-09-27

依据：[架构设计](../架构设计.md) · [技术设计](../技术设计.md) · [前端设计](../前端设计.md)

本文件为规划归档，实施前按对应里程碑补齐详细契约与验收规格。

## 1. 职责与边界

仅展示现有近 7 天可用率、最近响应速度和近期可用性记录，复用已有公开接口、后台配置和采集任务。首版不做速度历史和完整七天历史曲线，不扩展后端。

## 2. 结构与数据流

后台主动探测写入既有存储，公开状态接口返回汇总、最新响应耗时与近期状态点。前端直接展示七天可用率，用历史状态条呈现最多 60 个记录，并标出实际记录范围；不补齐不存在的时间点。

## 3. 关键决策

速度使用最近一次模型探测的响应耗时，网络往返耗时不能替代它。可用率使用后端已有七天汇总，近期历史保留正常、性能下降、不可用、未知的状态语义；不从 60 条记录推算七天可用率。保留公开开关及现有脱敏规则。

## 4. 当前实现

现有公开接口有七天可用率、最近响应耗时和最多 60 个状态点，已满足简化后的数据需求。新页面未实现；现网开关、监测项和样本数量未核实。本轮仅修改设计。

## 5. 验证方式

为前端状态转换、记录时间排序和缺失值处理编写必要的业务测试；核对接口样例与页面记录一致。检查未开启、无数据、部分缺测、失败和过期数据的展示；外观通过实际页面检查。此范围无需新增后端测试或实现。

## 6. 待扩展项

实施前按已有公开响应固定适配和展示规格；历史范围按实际返回记录确定。速度历史和更长窗口的历史汇总不纳入首版。
