# 公开状态

模块定位：官网可用率、当前响应速度和近期可用性记录。

对应代码：`frontend-portal/src/app/status/`、`src/features/status/`、`src/lib/api/public-server.ts`；复用既有 `backend/internal/service/public_status.go` 与渠道监测服务。

所属里程碑：[M1](../roadmap.md#m1) · 当前状态：进行中 · 最近更新：2026-09-27

依据：[架构设计](../架构设计.md) · [技术设计](../技术设计.md) · [前端设计](../前端设计.md)

详细契约见 [官网实施规格](../../design/public-site.md) 和 [状态页面规格](../../design/status.md)。

## 1. 职责与边界

仅展示现有近 7 天可用率、最近响应速度和近期可用性记录，复用已有公开接口、后台配置和采集任务。首版不做速度历史和完整七天历史曲线，不扩展后端。

## 2. 结构与数据流

后台主动探测写入既有存储，公开状态接口返回汇总、最新响应耗时与近期状态点。前端直接展示七天可用率，用历史状态条呈现最多 60 个记录，并标出实际记录范围；不补齐不存在的时间点。

## 3. 关键决策

速度使用最近一次模型探测的响应耗时，网络往返耗时不能替代它。可用率使用后端已有七天汇总，近期历史保留正常、性能下降、不可用、未知的状态语义；不从 60 条记录推算七天可用率。保留公开开关及现有脱敏规则。

## 4. 当前实现

只读适配和状态页已实现。页面展示总体状态、后端七天可用率和监测项数量，每项显示最近耗时、公开分组文案与历史状态条。历史按实际时间排序保留最近 60 点，不合成缺失时段；键盘聚焦和鼠标指向记录时可见其时间与状态。

无监测项或全部未知且没有有效历史时，不将后端默认零值展示成停机率；真实已知的 0% 和 0ms 保留。时间归一后以北京时间展示，额外后台字段不进入网页。后台代码、采集和公开设置均未修改。

## 5. 验证方式

已通过状态转换、ISO 日期有效性、排序与最多 60 点、缺失/零值、未知状态与字段隔离测试；工程检查与生产构建通过。离线预览使用实际状态组件，能切换正常、关闭、需登录、失败与空结果。

未访问现网，探测配置与样本数量尚未核实。当前无可用浏览器连接，实际渲染和点击/键盘验收仍待补。此范围无需新增后端测试或实现。

## 6. 待扩展项

实施前按已有公开响应固定适配和展示规格；历史范围按实际返回记录确定。速度历史和更长窗口的历史汇总不纳入首版。
