# 公开状态

模块定位：官网可用性、响应速度和历史趋势。

对应代码：`frontend-portal/src/features/status/`（规划）；既有 `backend/internal/service/public_status.go` 与渠道监测服务。

所属里程碑：[M1](../roadmap.md#m1) · 当前状态：未开始 · 最近更新：2026-09-27

依据：[架构设计](../架构设计.md) · [技术设计](../技术设计.md) · [前端设计](../前端设计.md)

本文件为规划归档，实施前按对应里程碑补齐详细契约与验收规格。

## 1. 职责与边界

仅实现已确认三项指标，复用现有后台探测配置和采集任务。公开页不提供内部渠道管理、供应商账号、配额或错误详情。

## 2. 结构与数据流

后台主动探测写入既有明细与汇总存储，公开状态服务提取对外数据，新前端展示当前指标与近 7 天历史。历史按时间聚合，应覆盖整个选择窗口，空缺区间保留空缺。

## 3. 关键决策

速度使用模型探测的响应耗时，网络往返耗时不能替代它。可用性沿用现有探测统计口径。需要为公开历史补响应耗时与完整窗口，不能把最近 60 次探测当成七天曲线。保留公开开关及现有脱敏规则。

## 4. 当前实现

现有公开接口有七天可用率、最近响应耗时和最多 60 个状态点；历史点没有延迟。公开数据扩展与新页面均未实现。现网开关、监测项和样本数量未核实。

## 5. 验证方式

对窗口、状态比例、延迟聚合、零样本和脱敏编写后端测试；图表使用接口样例与实际探测记录核对。检查未开启、无数据、部分缺测、失败和过期数据的展示。

## 6. 待扩展项

实施前确定公开历史响应结构、采样说明与缓存周期；严格保持三项范围。后端修改同步根目录原状态模块文档。
