# 账号与密钥

模块定位：注册登录、会话、账号设置及客户密钥管理。

对应代码：`src/features/auth/`、`src/features/keys/`、`src/features/settings/`、`src/features/console/`、`src/lib/api/` 和对应 `src/app/` 路由。

所属里程碑：[M2](../roadmap.md#m2) · 当前状态：进行中 · 最近更新：2026-09-28

依据：[架构设计](../架构设计.md) · [实施契约](../../design/customer-console.md) · [页面规格](../../design/console-pages.md)

## 1. 职责与边界

实现邮箱登录、个人/创建组织/加入组织注册、邮件恢复密码、已有双重验证、资料、改密、密钥增改停删、复制及按密钥查看用量。按公开配置显示第三方登录、通行密钥和验证码。组织管理页面归 M4。

## 2. 结构与数据流

路由仅接线。会话对象负责凭证恢复、续期、退出和迟到响应隔离；账号容器提供身份快照与业务操作。恢复时请求当前账号，不信任本地旧角色。客户查询键包含身份与全部筛选；换号取消并删除旧账号缓存，客户布局按身份重新挂载页面。

控制台首次打开时，额外等待浏览器的登录恢复结束，再决定是否跳去登录页。公开页面的初始匿名状态不能被当成用户已经退出；公开模型目录仍由服务端输出内容。接口失败后保留重试入口，初始化过程中已失效的异步结果不会放行跳转。

客户请求走固定白名单代理，包含固定内部地址、JSON 大小限制、超时、取消、同源写入检查和不缓存响应。付款路径另核实组织身份。第三方回调用窄范围 GET 代理；供应商回调指向门户域名，让启动、回调、pending 操作共享 Cookie。

开发时，代理与 Next 共用配置中的访问地址列表，同时支持本机与明确配置的隧道域名。写入来源必须匹配完整 origin；没有 Origin 的回调仅从已配置列表内解析转发域名，用于公开跳转与 Cookie 所属页面。未知转发头不能扩大允许范围，生产模式继续只使用固定公开地址。详见[开发隧道说明](../../README.md#通过-cloudflare-tunnel-访问-dev)。

2026-09-28 已将实际开发入口 `https://dev.chaosyn.com` 写入本机配置并重启服务。通过真实隧道验证，此来源的无凭据写入已进入身份鉴权并返回 401，未知来源仍返回 403；这项检查不等同于真实账号登录验收。详情见[开发隧道验证记录](../进度/2026-09-28-开发隧道.md)。

## 3. 关键决策

- 沿用 Bearer 协议，门户与原前端使用不同存储键。
- 同页共享续期，跨标签锁后重读凭证；退出、换号和组件重启阻断旧结果。网络、429和服务故障保留会话，明确失效才清理。
- 轮换响应缺少续期凭证时清空旧值。合法空昵称与组织摘要空状态原样保留，权限由底座核实。
- 密钥额度与周期限制均为美元金额，0为不限；创建有效期按天，编辑保留本地日期时间后转换。后端返回全值用于主动复制，不宣称只显示一次。
- TOTP 密钥只存当前弹窗内存，关闭、到期、换号即清理；迟到结果按代次丢弃。验证码以截止时间计时，可正确重复发送。
- 后端已知错误映射安全中文文案，不透传内部异常正文。

## 4. 当前实现

账号页顶部提供与官网相同的主题入口，偏好属于当前浏览器，不改变账号资料、会话或表单状态。详见 [主题切换](../../design/theme-switching.md)。

2026-09-28 账号入口按 [Proactiv 账号页规格](../../design/proactiv-redesign.md#6-其它页面层) 更新共用外观：桌面双栏品牌展示与表单，手机优先表单。登录、注册、找回与重置继续复用同一个账号外壳；登录恢复标记、配置开关、提交处理与错误恢复保持既有实现。

2026-09-28 登录页左侧展示区复用首页聚光灯（手机隐藏该区）；登录、注册、找回密码与第三方补充注册表单的输入框改用带悬停光晕的账号页输入框，校验、禁用、触控高度与焦点样式沿用原输入框。控制台输入框不加光晕。注册方式（个人 / 创建组织 / 加入组织）切换加选中滑块。规格见[前端设计 · 共享动效组件](../前端设计.md#共享动效组件)。

账号页、客户守卫、设置与密钥界面已接入。OAuth 支持 fragment 凭证、pending 注册/绑定/补邮箱与 GitHub/Google 注册完成，回调清除 URL 凭证并兼容旧控制台返回路径；Passkey 复用 begin/finish。验证码只按实际启用配置加载。

组织邀请链接可以预填邀请码并选择加入组织；用户改为个人或创建组织时清空旧邀请码，避免串用注册方式。组织管理导航按所有者身份开放，普通成员从概览进入本人配额申请，具体规则见[组织与成员](组织与成员.md)。

控制台侧栏只标注个人、组织管理员或组织成员身份，账号设置固定在底部，退出登录保留在设置页；真实昵称继续在个人资料表单编辑。隔离测试中修改昵称后恢复原值，避免测试内容残留在验收页面。

供应商登记地址及底座 OAuth redirect URL 必须一致填写 `https://门户域名/api/portal/auth/oauth/<provider>/callback`；底座前端回调 URL 指向门户 `/auth/.../callback`。不能将回调指向另一后端域名，否则浏览器 Cookie 不会随行。通行密钥 RP ID 与来源同样需匹配门户域名。

## 5. 验证方式

独立单测覆盖续期竞争、跨标签退出/换号、存储故障、StrictMode 重订阅、代理边界、返回地址、密钥金额与有效期。独立评审发现的会话、TOTP 生命周期、密钥跳转和 SDK 竞争问题已修复。

新增实际 React 首次加载回归：已有登录记录但校验尚未返回时不跳登录；服务故障时显示重试并可恢复进入；确认没有登录记录后才跳登录。测试使用 JSDOM 执行组件初始化和 StrictMode 流程，检验身份与导航行为，不断言样式，也不作为真实浏览器截图验收。

2026-09-28 最终实现通过完整工程门禁（23 个测试文件、979 项测试）和生产构建。真实本地接口另验证了登录、保存后的恢复、401 后续期及服务故障退出等待；本地生产预览已更新相同修复。

隔离 Go/PostgreSQL/Redis/Mailpit 已走通邮箱注册、登录、真实续期、资料修改、密钥增改停删、TOTP 开启/登录验证/关闭、邮件找回与新密码登录、创建组织和邀请加入、成员配额读取与门户充值拒绝。没有真实邮件外发或模型调用。

浏览器连接不可用，未记录实际点击或手机渲染通过。真实 OAuth 账号、通行密钥设备和外部验证码供应商未配置，需在启用时联调。
