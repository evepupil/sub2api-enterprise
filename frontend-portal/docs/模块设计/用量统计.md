# 用量统计

模块定位：个人总览、调用明细与统一精确时间范围。

对应代码：`frontend-portal/src/features/usage/`、`src/lib/time/`、`src/components/charts/`（规划）；既有用量处理与查询层。

所属里程碑：[M3](../roadmap.md#m3) · 当前状态：未开始 · 最近更新：2026-09-27

依据：[架构设计](../架构设计.md) · [技术设计](../技术设计.md) · [前端设计](../前端设计.md)

本文件为规划归档，实施前按对应里程碑补齐详细契约与验收规格。

## 1. 职责与边界

覆盖页面 9、11：余额或配额、请求/Token/实际消费/平均耗时、三类分布与表格、Token 趋势、逐条明细。概览不包含最近调用列表。

## 2. 结构与数据流

时间控件生成统一的起止边界、时区与粒度，传给所有区间查询；缓存按身份和全部筛选隔离。汇总、分布和趋势各自显示加载/错误，只有匹配当前范围的响应才能更新页面。

## 3. 关键决策

补充精确时间入参并兼容旧日期参数，统一包含开始、不包含结束的边界。近 24 小时使用真实时间差；日历预选按用户时区计算。四类 Token 与实际消费沿用后端口径；当前余额独立查询。

## 4. 当前实现

已有用户区间汇总、模型/分组/接口分布与趋势接口。自定义起止目前只接受日期；小时趋势格式包含日期，支持跨日聚合。精确时间扩展、新控件和统计页面尚未实现。

## 5. 验证方式

核心测试覆盖滚动 24 小时、时区和跨日边界、同一范围汇总一致性、快速切换、旧响应、精度及无数据。后端扩展测试兼容旧查询；实际核对分项与合计、账户角色和每把密钥筛选。

## 6. 待扩展项

模块实施时固定统计响应、分页和时间控件约定，同步受影响的原后端用量模块文档。额外统计维度另行排期。
