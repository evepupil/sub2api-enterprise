# 用量统计

模块定位：个人总览、调用明细与统一日期范围。

对应代码：`frontend-portal/src/features/usage/`、`src/lib/time/`、`src/components/charts/`（规划）；既有用量处理与查询层。

所属里程碑：[M3](../roadmap.md#m3) · 当前状态：未开始 · 最近更新：2026-09-27

依据：[架构设计](../架构设计.md) · [技术设计](../技术设计.md) · [前端设计](../前端设计.md)

本文件为规划归档，实施前按对应里程碑补齐详细契约与验收规格。

## 1. 职责与边界

覆盖页面 9、11：余额或配额、请求/Token/实际消费/平均耗时、三类分布与表格、Token 趋势、逐条明细。概览不包含最近调用列表。

## 2. 结构与数据流

日期控件生成统一的起止日期、时区与趋势粒度，传给所有区间查询；缓存按身份和全部筛选隔离。汇总、分布和趋势各自显示加载/错误，只有匹配当前范围的响应才能更新页面。

## 3. 关键决策

只选日期，复用现有日期参数。预选今天、昨天、近 7/14/30 天、本周、本月、上月和自定义日期，取消近 24 小时与时分输入；近 N 天含今天，共 N 个日历日。前端明确传入起止日期和时区，由后端将结束日扩展到次日零点，避免默认相对周期带入当前时刻。四类 Token 与实际消费沿用后端口径；当前余额独立查询。

## 4. 当前实现

已有用户区间汇总、模型/分组/接口分布与趋势接口，自定义起止日期满足当前需求。图表聚合粒度和查询日期范围分别处理，不增加时分选择。新控件与统计页面尚未实现，取消本模块精确时间后端扩展。

## 5. 验证方式

核心测试覆盖日历预选、开始/结束日、时区与跨月边界、同一范围汇总一致性、快速切换、旧响应、金额精度及无数据。实际核对分项与合计、账户角色和每把密钥筛选；无需为已取消的精确时间扩展修改后端。

## 6. 待扩展项

模块实施时按现有接口固定响应适配、分页和日期控件约定。额外统计维度和更细的查询时间另行讨论。
