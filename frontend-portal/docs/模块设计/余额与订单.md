# 余额与订单

模块定位：余额充值、充值订单和到账状态。

对应代码：`frontend-portal/src/features/billing/`（规划）；既有支付、订单和余额接口。

所属里程碑：[M3](../roadmap.md#m3) · 当前状态：未开始 · 最近更新：2026-09-27

依据：[架构设计](../架构设计.md) · [技术设计](../技术设计.md) · [前端设计](../前端设计.md)

本文件为规划归档，实施前按对应里程碑补齐详细契约与验收规格。

## 1. 职责与边界

覆盖页面 12。首版只做余额充值和订单，付款入口按现有角色与配置提供。普通组织成员展示配额，付款关系沿用组织管理员余额结算。

## 2. 结构与数据流

查询余额和可用支付方式，后端创建订单，客户完成支付后查询订单状态，再刷新余额。支付通知仍由后端接收和校验；网页回跳只用于触发查询。

## 3. 关键决策

订单状态与到账以服务端为准；不因支付回跳直接显示成功。创建订单等写操作超时后先查状态，不盲目重试。现有充值金额/币种规则照实际支付配置，模型美元报价不推导支付币种。

## 4. 当前实现

已有充值与订单接口，本轮未验证实际支付通道配置。新页面和支付回跳联调尚未实施。

## 5. 验证方式

验证订单待支付、成功、关闭、取消或失败等实际支持状态；检查重复操作、回跳刷新、超时恢复和权限。需要支付验证时按用户授权的测试环境执行，不擅自发起真实付款。

## 6. 待扩展项

套餐、自动充值、发票和合同继续后置。实施前明确回跳地址与订单查询节奏。
