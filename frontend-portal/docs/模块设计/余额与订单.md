# 余额与订单

模块定位：余额充值、付款入口与订单到账状态。

对应代码：`src/features/billing/`、`src/app/console/billing/`、`src/app/payment/result/`、客户代理的付款权限检查。

所属里程碑：[M3](../roadmap.md#m3) · 当前状态：进行中 · 最近更新：2026-09-28

依据：[架构设计](../架构设计.md) · [实施契约](../../design/customer-console.md) · [页面规格](../../design/console-pages.md)

## 1. 职责与边界

只做余额充值和订单，个人与组织所有者可付款。普通成员使用配额，页面与门户服务端共同阻止充值。套餐、自动充值、发票、合同继续后置。

## 2. 结构与数据流

查询当前资金、配置和订单，底座创建订单，前端根据真实返回选择跳转、二维码、Stripe、Airwallex 或微信。二维码本地生成，支付秘密仅存当前内存，关闭后只保留订单编号供恢复查询。

待支付/已支付/入账中每3秒查一次，前一请求结束才排下一次；失败可手动重试，终态停止。只有 COMPLETED 刷新余额并显示到账，付款入口仅在 PENDING 显示。

## 3. 关键决策

- 开关字段是 `enabled`；真实手续费取顶层 `recharge_fee_rate`，单位为百分数。
- 输入和付款按通道币种，缺省CNY；订单 amount 已是入账美元，不能再乘倍率。最终资金以后端为准。
- 按币种支持0/2/3位小数，手续费向上取整到最小单位；十进制计算避免多进1分钱。
- 日上限和实际剩余分开，未知不猜测；底座最终校验可用额度。
- 底座固定回跳 `/payment/result`；入口仅提取订单编号并转控制台查询，丢弃 URL 成功标记及付款凭证。
- 配置门户公开地址与内部底座地址，向底座转发可信站点来源核对回跳；不提供任意代理。
- 创建订单不自动重试，超时先查已有订单。SDK 在卸载/换单后丢弃迟到结果，提交中防重复。

## 4. 当前实现

Stripe 外观从共享颜色生成，主题变化时更新已有付款组件，保留正在填写的内容和订单会话；卸载或换单释放主题订阅。外观更新失败不会中断付款流程，未以本地样例代替真实供应商验收。详见 [主题切换](../../design/theme-switching.md)。

2026-09-28 随 [Proactiv 整站改版](../../design/proactiv-redesign.md) 统一余额、订单与支付界面外观。按量余额模式继续保留；订单金额、状态、到账与付款跳转均使用实际接口，首页营销内容不参与资金业务。

余额/冻结金额、充值表单、费率和入账预估、订单筛选分页、取消、回跳查询及付款适配均已实现。关闭充值不影响历史订单；无付款入口时只查询与取消，不伪造链接。2026-09-28 充值预设金额按钮加选中滑块（控制台节奏 180ms），按钮选中语义不变，规格见[前端设计 · 共享动效组件](../前端设计.md#共享动效组件)。同日按[控制台质感改版](../../design/console-refresh.md)，订单的到账金额改用控制台统一的美元写法（`$` 加两位小数，原先显示为 `US$`）；付款金额仍按支付通道币种显示。

## 5. 验证方式

独立业务测试覆盖金额、上限、币种精度、手续费、状态、返回地址与成员权限；独立评审复核终态付款入口和 SDK 竞争修复。

隔离 Go/PostgreSQL/Redis 和本地模拟支付完成：下单、取消、新订单、正确签名通知、COMPLETED、余额核对。20 CNY充值、2%费率实付20.40 CNY，0.14倍率到账2.80 USD。没有真实付款、线上配置变更或模型调用。

真实 Stripe/Airwallex/微信及线上供应商尚未配置，需测试通道浏览器联调后启用。浏览器工具无连接，HTTP与状态验证不当作点击验收。

## 6. 待扩展项

M5 核对正式域名、供应商回调和支付通知路由；套餐等保留原取舍。

## 控制台文案修正

支付配置缺失时只提示“支付暂不可用”及重试/更换方式，不向客户展示内部密钥或支付参数名称。预估手续费与付款恢复说明保留必要的金额含义和下一步操作，删除“后端返回”“本页面没有保存入口”等实现用语。充值权限、订单状态与实际到账判断保持既有规则。
