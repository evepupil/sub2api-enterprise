# 独立客户前端需求设计

状态：已定稿（首版范围） · 最近更新：2026-09-27

关联资料：[竞品调研](../../docs/调研/2026-09-26-AI-API服务站/00-调研结论与待选方向.md) · [现有底座能力](../../docs/调研/2026-09-26-AI-API服务站/11-现有底座与前端边界.md) · [既有项目路线图](../../docs/roadmap.md)

本文件属于重新设计的独立客户前端。既有项目的 M1 组织业务、M2 原界面改造、M3 安全对接提供背景和可复用能力；新前端的里程碑见 [独立路线图](./roadmap.md)，与原项目分别管理。

## 1. 已确认的定位

基于现有 Sub2API 业务底座，重新做一套面向高价值客户的独立前端，提供成熟、专业的在线软件服务体验。

用户已认可的总体范围为对外官网与登录后的客户控制台：官网帮助客户了解和选择服务，控制台承接日常使用，二者共享品牌和设计规范。

## 2. 已确认的方向

- 复用现有账号、密钥、模型、充值、计费、用量和组织等业务能力。
- 围绕选模型、接入、充值、查消费、管理密钥和按需要管理团队组织客户流程。
- 界面视觉统一，信息完整，价格容易理解，操作清楚，适合长期使用。
- 神稳 AI 提供功能与流程参考，其他平台用于比较模型选型、费用展示、团队管理及界面组织。
- 接入文档归入帮助内容，不单列为产品差异化能力。
- 消费与服务提醒延后做。
- 首版只做余额充值，保留充值订单与到账查询；套餐购买后置。
- 在线模型试用首版不做，后置。
- 企业采购扩展首版不做。
- 账号、模型与价格、密钥和团队的十三项功能及边界已确认；平台管理员继续使用现有管理后台。
- 官网状态监控首版做，范围只包含可用性、速度和历史趋势。
- 模型列表采用紧凑卡片，每张卡片只放厂家标志与名称、模型代号，以及输入、缓存写入、缓存读取、输出四项美元价格。
- 模型卡片的价格复用 Sub2API 现有数据；接入示例、能力介绍、计费说明等文字从卡片中移除，独立模型详情页继续取消。
- 整站共十四个页面，页面范围和内容已确认。
- 已选定 A 灰白黑视觉方向，按紧凑卡片调整；后续讨论品牌细节、技术选型、目录与部署方式。
- 首页使用 Aceternity UI 提升首屏与产品展示质感，保留 A 风格。
- 概览移除最近调用，增加汇总统计、模型等维度的环形分布与用量金额表、Token 趋势；时间范围提供多种预选与自定义起止，所有统计统一联动。

## 3. 使用者与当前业务背景

具体优先客群尚未确定。现有底座的客户身份包括个人用户、组织管理员和普通组织成员。

| 现有身份 | 当前业务背景 | 新前端需要说明的内容 |
|---|---|---|
| 个人用户 | 使用本人余额、密钥和调用记录 | 本人可用额度与实际消费 |
| 组织管理员 | 以本人余额承担组织消费，管理成员和配额 | 组织支出、成员额度及资金情况 |
| 普通组织成员 | 在组织授权与个人消费配额内使用，消费由组织管理员余额结算 | 本人可用配额与用量 |

一个账号最多属于一个组织是当前底座规则。多组织切换、更多管理角色等扩展尚未提出为本次需求。

## 4. 功能大类与当前取舍

当前已明确：F 首版只做余额充值与订单，套餐购买后置；I、J 延后；K 首版不做；L 首版。其他大类按下文已确认功能与页面范围实施。

| 编号 | 大类 | 范围 | 当前安排 |
|---|---|---|---|
| A | 对外官网 | 服务介绍、模型范围、计费说明、开通入口 | 首版 |
| B | 账号与安全 | 注册登录、找回密码、个人资料、账号安全设置 | 首版，遵循现有注册规则 |
| C | 模型与价格 | 紧凑模型卡片、搜索筛选；仅厂家标志与名称、模型代号和四项美元价格 | 首版，四价顺序为输入、缓存写入、缓存读取、输出 |
| D | 密钥管理 | 创建、命名、停用、删除、额度和有效期设置 | 首版，细项核对现有能力 |
| E | 工作台与用量 | 余额或配额、区间统计、模型/分组/接口分布、Token 趋势、调用记录与费用明细；灵活时间范围 | 首版；最近调用摘要从概览移除 |
| F | 余额充值与订单 | 余额充值、充值订单、到账查询，按现有规则消费扣费 | 首版；套餐购买后置，用户已确认 |
| G | 团队管理 | 创建或加入组织、邀请成员、分配消费配额、组织用量 | 首版，用户已确认；沿用现有组织规则 |
| H | 帮助与服务信息 | 接入文档、常见问题、公告、客服入口；状态监控独立归 L | 首版 |
| I | 消费与服务提醒 | 余额不足、配额将尽、重要服务主动通知 | 以后做，用户已确认 |
| J | 在线模型试用 | 文字测试、图片生成体验、历史结果 | 以后做，用户已确认 |
| K | 企业采购扩展 | 开票、合同、更多权限及企业登录 | 首版不做，用户已确认 |
| L | 官网公开状态监控 | 可用性、速度、历史趋势，见 [状态监控需求讨论](./状态监控需求讨论.md) | 首版，三项范围已确认 |

## 5. 体验要求

- 官网与客户控制台共享一套品牌和设计规范，信息密度适合各自任务。
- 价格、计费单位、余额与配额的含义清楚，展示与实际业务一致。
- 功能与能力说明使用真实产品材料，竞品宣传数字不作为本项目事实。
- 页面设计阶段覆盖加载、空数据、错误、长文本与不同屏幕尺寸。

## 6. 已确认功能批次

用户已确认下列十三项。后续继续按一批相关内容统一核对。

| 编号 | 类别 | 确认范围 |
|---|---|---|
| 1 | 账号 | 注册、登录、找回密码，沿用现有注册规则 |
| 2 | 账号 | 修改个人资料与密码 |
| 3 | 账号 | 保留底座已有的双重验证能力 |
| 4 | 模型与价格 | 未登录也能浏览模型和价格 |
| 5 | 模型与价格 | 按模型名称、厂商搜索和筛选 |
| 6 | 模型与价格 | 模型卡片仅展示厂家标志与名称、模型代号，以及输入、缓存写入、缓存读取、输出四项美元价格，不设独立详情页 |
| 7 | 密钥 | 创建、编辑、停用和删除密钥 |
| 8 | 密钥 | 设置允许的使用范围、消费额度和有效期，遵循底座权限 |
| 9 | 密钥 | 查看每把密钥的用量与消费 |
| 10 | 团队 | 按现有规则创建或加入组织 |
| 11 | 团队 | 邀请、启用或停用成员，分配消费配额 |
| 12 | 团队 | 管理员查看组织总用量，并按成员查询 |
| 13 | 后台边界 | 平台管理员继续使用现有管理后台，本次重做客户前端 |
