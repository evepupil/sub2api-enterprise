## 登录验证停留问题

- 用户反馈控制台长期停在“正在验证登录状态”。本地核实前端仍在运行，Go 进程已停止，登录代理返回 502；恢复了原隔离后端，并将前后端通过隐藏后台进程保持运行。
- 开发日志另外记录了 127.0.0.1 的页面更新连接被拦。默认开发命令固定使用已验证的 Webpack 与回环地址；仅允许明确的两个本机来源。修复前 127.0.0.1 的升级连接被拒，修复后为 101，未信任来源仍被拒绝。
- 用低成本内置独立测试任务补 React 首次加载回归（Fleet 运行器此前临时扩展加载失败，未在本轮修全局工具）。复现出已保存登录信息、身份请求未完成时已经两次跳去登录页；主控确认了同样的失败。
- 最终修复由账号容器标记登录恢复是否结束，控制台仅在恢复结束且确认匿名时跳登录。独立复核确认公开目录的服务端内容、登录表单和 OAuth 行为保持原有边界。
- 本轮主控直接实现为一批小型修正：开发入口、账号初始化标记与私有页面跳转条件；独立测试任务仅写认证回归，未改实现。真实本地 API 验证已覆盖登录、保存后恢复、401 后续期，以及后端错误退出等待状态。
- 最终实现的 `pnpm check` 全部通过：格式、静态分析、严格类型、23 个测试文件 / 979 项测试及生产构建；Linux 容器镜像构建通过。
- 本地 18088 预览已更新为本次修复镜像并通过健康检查；3000 开发入口保持运行。两处控制台 HTML、全部引用的脚本与样式（分别 24、10 个）均返回 200，8080 后端健康检查返回 200。以上为接口与资源验证，浏览器实际点击仍未验收。
