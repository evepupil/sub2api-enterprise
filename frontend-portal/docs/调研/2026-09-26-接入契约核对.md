## 1. 登录与身份

| 已有能力 | 核对结论 | 源码证据 |
|---|---|---|
| 登录凭证 | 登录、注册和双重验证成功通常返回访问凭证、续期凭证、有效期与用户；签发失败时有只返回访问凭证的降级分支 | [账号处理](../../../backend/internal/handler/auth_handler.go)，120–152 行 |
| 请求身份 | 当前后端从请求头读取 Bearer 凭证，Cookie 本身不能替代它；原前端把凭证保存在浏览器本地存储 | [鉴权中间件](../../../backend/internal/server/middleware/jwt_auth.go)，40–56 行；[原请求封装](../../../frontend/src/api/client.ts) |
| 续期 | 后端轮换续期凭证；旧前端已有同页单次刷新、跨标签锁与等待其他标签写回的处理，新前端需保留这些语义 | [续期服务](../../../backend/internal/service/auth_service.go)，1885–1968 行；[原续期处理](../../../frontend/src/api/tokenRefresh.ts)，127 行起 |
| 退出 | 退出入口按传入的续期凭证撤销续期，并清理本地；不能由此声称已发出的访问凭证全部立即失效 | [账号路由](../../../backend/internal/server/routes/auth.go)，58、257–259 行；[账号处理](../../../backend/internal/handler/auth_handler.go)，751–793 行 |
| 身份与组织 | 平台管理员字段与组织归属分别返回；组织管理员依据组织摘要中的所有者信息判断，不能用平台角色代替 | [用户数据结构](../../../backend/internal/handler/dto/types.go)，12–48 行 |

新前端决定：沿用浏览器访问凭证协议；私有页面在浏览器恢复会话后查询。公开页面服务端输出匿名内容，私有数据不进入公开缓存。客户前端使用独立的本地存储命名和刷新协调名称。

找回密码同时涉及 `/forgot-password` 与 `/reset-password`，属于同一恢复流程的两个路由状态，不增加产品页面范围。已启用的第三方登录回调、通行密钥和验证码配置在账号模块实施时核对，只承接真实已启用能力。

## 2. 部署与模型调用路径

现有 Go 构建会将原 `frontend/` 产物嵌入程序；未知网页路径回落到旧首页。仓库的代理模板当前把网站请求整体转给 Go，尚无新 Next.js 服务的分流配置。

证据：[Dockerfile](../../../Dockerfile)，23、44、84 行；[路由装配](../../../backend/internal/server/router.go)，74–90 行；[内嵌界面](../../../backend/internal/web/embed_on.go)，355–370 行；[代理模板](../../../deploy/Caddyfile)。模板不能代表现网配置。

| 路径或用途 | 目标 | 处理约定 |
|---|---|---|
| `/api/v1/*` | Go | 包含登录、客户业务、支付通知等现有接口；权限继续由后端控制 |
| `/v1/*`、`/v1beta/*` | Go | 保留模型接口原路径与流式响应 |
| `/backend-api/*`、`/antigravity/*` | Go | 保留既有客户端兼容入口 |
| `/models`、`/responses` 及子路径、`/messages/count_tokens` | Go | 根路径模型接口不得被网页路由覆盖 |
| `/chat/completions`、`/embeddings`、`/alpha/search`、`/web_search`、`/x_search` | Go | 按现有注册的方法和路径保留兼容入口 |
| `/images/*`、`/videos` 及子路径、`/tts`、`/stt`、`/realtime`、`/custom-voices` 及子路径 | Go | 保留已有 API；不因此在客户前端增加在线试用功能 |
| `/health` | Go | 保留既有健康检查 |
| `/catalog`、网站页面、`/console/*`、网页静态资源 | 新前端 | 模型目录选 `/catalog`，避开已有 `/models` API |
| 原管理域名全部页面 | Go 与旧前端 | 建议独立管理入口，保留旧前端路由体系 |

模型路径证据：[网关路由](../../../backend/internal/server/routes/gateway.go)，185、339、365–375、390–511 行。支付通知位于 [支付路由](../../../backend/internal/server/routes/payment.go) 的 `/api/v1/payment/webhook/*` 下。

有一项需在联调验证：部分根路径模型别名已注册，但未列入现有内嵌网页让行规则。应检查其响应是否被旧首页截获；如复现，再在对应路由模块做最小修正。本轮仅记录源码风险，未将它写成已复现故障。

入口代理应保留流式传输和 WebSocket，并按实际部署传递可信客户端地址。服务端网页请求只读匿名公开数据，不代替客户浏览器调用绑定身份的业务接口。

## 3. 公开模型与价格

已有 `/api/v1/model-plaza` 支持可选身份：匿名可访问取决于公开开关、要求登录设置和运行模式。用户专属分组和个人倍率需要按登录身份隔离。

证据：[模型路由](../../../backend/internal/server/routes/model_plaza.go)，17–31 行；[模型处理](../../../backend/internal/handler/model_plaza_handler.go)，107–165 行。四价与倍率核对见 [价格来源](../前端设计/模型价格来源核对.md)。

结论：可复用现有接口，不需要新增公开模型详情接口。实际售价展示必须按现有有效倍率和计费条件转换，不能直接使用样稿的仓库参考价。

## 4. 公开状态

已有 `/api/v1/status` 匿名入口，受公开开关和限流控制。它提供七天探测可用率、最近响应耗时、网络耗时以及状态时间线；当前时间线每点只有状态和时间，缺少响应耗时。

证据：[状态路由](../../../backend/internal/server/routes/public_status.go)；[公开状态结构与转换](../../../backend/internal/service/public_status.go)，41–76、174–205 行。现有总体可用率是各监测项可用率的算术平均，不能称为按请求流量加权的成功率。

当前用户监测视图最多给出 60 个状态点，不能直接用于完整七天趋势。底座已有主动探测、明细与汇总存储。首版在原监测服务内补公开历史聚合和延迟字段，保持公开开关、指标含义与脱敏范围。

证据：[监测采集](../../../backend/internal/service/channel_monitor_runner.go)、[监测常量](../../../backend/internal/service/channel_monitor_const.go)、[监测仓储](../../../backend/internal/repository/channel_monitor_repo.go)。公开项的延迟缺失和完整窗口扩展在 M1 验收。
